# 功能规格：Wear OS 伴侣 App

## 功能名称

Wear OS 伴侣 App

---

## 用户入口

- 用户在 Wear OS 手表上直接打开配套 App（点击图标或通过应用列表）。
- 该 App 作为手机端主 App 的配套模块安装，需要手机端 App（Play 渠道版本）同时安装并处于同一账号下配对。

---

## 输入

- 手机端推送的显示快照（包含计划列表、雌二醇估算值、最近一次服药记录）。
- 用户在手表上执行的操作：快速记录（Log）、跳过（Skip）、撤销最近记录（Undo）。
- 用户打开 App 时触发的主动刷新请求。

---

## 输出

### 主屏幕内容（从上至下）

1. **App 名称**（居中标题）
2. **今日进度计数**：格式为"已完成数 / 总计划数"（例：1 / 3），使用辅助色文字。
3. **估算雌二醇卡片**（仅当手机端有 PK 投影数据时显示）：
   - 当前估算值（前缀"~"，附单位，例：`~92 pg/mL`）
   - 近 48 小时平滑曲线图（折线图，左端标注"48 小时前"，右端标注"现在"）
   - 估算免责声明文字（小字，居中）
4. **"上一次记录"区块标题**，下方显示：
   - 药物组名称
   - 药物摘要（药名 · 剂量 · 给药途径，若隐藏药物详情则为空）
   - 记录时间（MM-DD HH:mm 格式）
   - "撤销记录"按钮（仅当该记录可撤销时显示）
5. **"接下来五项"区块标题**，下方显示最多五项计划卡片：
   - 第一项（可操作项）：使用突出颜色卡片，显示组名、计划时间、药物摘要、状态，以及"记录"和"跳过"两个操作按钮
   - 第二至五项：普通卡片，显示时间 · 组名、药物摘要、状态文字（只读，无按钮）
6. **空状态**：若无计划则显示"所有计划已完成"文字。

### 操作反馈状态（第一项卡片内）

| 操作阶段 | 显示内容 |
|---|---|
| 正在发送 | "正在同步…"（按钮隐藏） |
| 已发送 | "已发送"（按钮隐藏，约 1.5 秒后自动恢复） |
| 发送失败 | "无法连接手机"，并重新显示按钮 |

### 撤销按钮反馈状态

| 操作阶段 | 按钮文字 |
|---|---|
| 默认 | "撤销记录" |
| 正在发送 | "正在同步…" |
| 已发送 | "已发送"（约 1.5 秒后请求刷新快照） |
| 发送失败 | "无法连接手机"（2 秒后按钮恢复可用） |

## 用户操作流程

### 查看计划

1. 用户打开手表 App。
2. App 立即从本地加密缓存读取快照并渲染屏幕。
3. 同时向手机请求最新快照（打开 App 时始终请求，不受缓存新鲜度限制）。
4. 收到手机返回的新快照后，屏幕自动更新。

### 快速记录（记录当前第一项可操作计划）

1. 用户点击第一张卡片上的"记录"按钮。
2. 卡片立即切换到"正在同步…"状态，按钮消失。
3. 命令发送至手机；若成功，卡片显示"已发送"约 1.5 秒。
4. 1.5 秒后：该条目从列表中隐藏（本地乐观排除），同时向手机请求最新快照。
5. 手机返回新快照后，屏幕以权威数据更新，本地乐观排除状态清除。
6. 若发送失败，卡片显示"无法连接手机"，2 秒后恢复按钮可用。

### 跳过（跳过当前第一项可操作计划）

流程与"快速记录"相同，操作结果为该计划在手机端被标记为已跳过，14 天内不再出现在计划列表中。

### 撤销上一次记录

1. 用户点击"上一次记录"卡片中的"撤销记录"按钮。
2. 按钮切换为"正在同步…"并禁用。
3. 命令发送至手机；若成功，按钮显示"已发送"，约 1.5 秒后请求刷新快照。
4. 手机新快照到达后，屏幕更新（被撤销的记录消失，对应计划重新出现在列表中）。
5. 若发送失败，按钮显示"无法连接手机"，2 秒后恢复可用。

---

## 状态变化

### 计划槽状态（可观察标签与颜色）

| 状态 | 显示文字 | 卡片/文字颜色 |
|---|---|---|
| 已完成（DONE） | "已完成" | 默认 |
| 即将到期（DUE_SOON） | "即将到期" | 主色调（高亮） |
| 已逾期（OVERDUE） | "已逾期" | 错误色（红色） |
| 待服（UPCOMING） | "待服" | 默认 |
| 窗口外已记录（LOGGED_OUT_OF_WINDOW） | "已在窗口外记录" | 默认 |

### 可操作条件

"记录"和"跳过"按钮仅在状态为"即将到期"、"已逾期"或"待服"时显示。

### 空快照状态

若本地没有快照（首次配对或数据清除后），屏幕中央显示 App 名称和"请打开手机端应用"提示文字，无其他内容。

## 数据字段的业务含义

| 字段 | 业务含义 |
|---|---|
| 今日进度（已完成 / 总计划数） | 当日快照中所有计划的完成状态汇总，帮助用户快速判断当天服药进度 |
| 估算雌二醇当前值 | 基于已记录剂量、由手机端 PK 模型计算的最新估算浓度；非实验室检测值 |
| 近 48 小时曲线 | 25 个采样点、每点间隔 2 小时的浓度历史曲线，帮助用户了解浓度变化趋势 |
| 计划组名 | 该服药计划所属的药物组名称 |
| 药物摘要 | 药名、剂量、给药途径的简短描述；若用户开启"隐藏药物详情"则为空 |
| 计划时间 | 计划预定服药的日期+时间（若与当日相同仅显示时间，跨日则显示 MM-DD HH:mm） |
| 最近服药记录时间 | 手机端最近一条服药记录的实际记录时间 |
| 可撤销标记 | 手机端为该记录附带了可撤销的 entry UUID 列表；存在列表时才显示"撤销"按钮 |

## 边界情况

- **隐藏药物详情**：若手机设置启用了"隐藏药物详情"，药名、剂量和给药途径字段在快照到达手表前即已清空，App 仅显示组名和时间。
- **跨日计划**：后续五项计划可跨越日期边界，跨日计划显示"MM-DD HH:mm"，当日计划只显示"HH:mm"。
- **无 PK 数据**：若手机快照中不含雌二醇估算数据，估算卡片不显示，进度计数直接显示在标题下方。
- **计划列表为空**：所有计划已完成时，第一张卡片区域显示"所有计划已完成"文字。
- **重复操作防护**：发送操作期间，按钮禁用，防止重复提交。
- **快照版本权威性**：手机返回新快照后，之前本地乐观隐藏的条目全部重置，以手机数据为准。

---

## 错误状态

| 错误场景 | 用户可观察的表现 |
|---|---|
| 手机未连接或不可达 | 操作后显示"无法连接手机"文字，约 2 秒后操作按钮恢复 |
| 快照不存在（初始状态） | 全屏显示 App 名称 + "请打开手机端应用" |
| 快照解密失败 | 与"快照不存在"表现相同（视为无快照） |
| 操作命令发送失败 | 操作按钮显示失败文字，恢复可重试状态 |

---

## 离线行为

- **手表有缓存快照**：离线时可正常显示上次收到的计划列表、雌二醇估算和最近记录；信息可能已过时，但不会提示"离线"标签。
- **尝试执行操作**：若手机不可达，记录/跳过/撤销命令无法送达，操作结果显示失败状态并恢复按钮。
- **数据不会在手表本地更新**：手表不独立存储或修改服药记录，所有写入操作必须经由手机执行。

---

## 重启后的行为

- **手表重启**：缓存快照在重启后仍可读取（持久化存储），App 打开后立即渲染上次快照，同时向手机请求最新快照。
- **手机重启**：手机重启后仍可通过 Wearable Data Layer 接收来自手表的命令；下次手表与手机通信时，手机端自动推送最新快照。
- **备份排除**：手表端缓存快照不参与系统备份，手表恢复出厂设置后缓存清空，需重新从手机同步。

---

## 可观察的同步行为

| 触发时机 | 手表行为 |
|---|---|
| 用户打开 App | 立即向手机发送快照请求（强制刷新，不受缓存时间限制） |
| 执行记录/跳过/撤销成功后约 1.5 秒 | 向手机发送快照请求 |
| 后台被动刷新 | 若缓存缺失，每 30 秒重试一次；若缓存存在但超过 30 分钟，每 5 分钟重试一次 |
| 手机推送新快照 | Data Layer 监听服务收到后立即写入本地缓存，UI 自动更新 |
| 手机推送新快照（乐观排除重置） | 新快照到达时，所有本地乐观排除的条目清除，以手机数据为准 |

---

## 与其他功能的关系

- **手机主 App**：手表 App 是手机端的只读镜像和有限操作终端，不独立管理计划或记录。
- **Wear OS Tile**：与手表 App 共享同一份加密缓存快照；Tile 操作也会触发快照刷新，影响 App 的显示。
- **手机桌面小组件**：手机端小组件快照是手表快照的数据来源（手表快照由手机端小组件快照派生）。
- **提醒系统**：记录和跳过操作成功后，手机端会重新调度提醒，已跳过的计划槽在 14 天内不再提醒。
- **库存管理**：记录操作成功后，手机端自动扣减对应药品库存。
- **"隐藏药物详情"设置**：该设置在手机端生效，影响推送到手表的快照内容。

## 独立实现所需的验收测试列表

以下测试以用户可观察行为为标准，不含代码实现细节：

1. **空快照状态**：在从未同步过的手表上打开 App，应显示 App 名称和"请打开手机端应用"提示，不显示任何计划或数据。

2. **快照加载与渲染**：手表收到第一条快照后，屏幕应显示进度计数、雌二醇卡片（若有数据）、最近记录（若有）、最多五项计划。

3. **进度计数准确性**：今日进度计数应与快照中当日已完成计划数和总计划数一致。

4. **计划状态颜色**：逾期计划卡片应使用红色/错误色；即将到期计划应使用主色调高亮；待服和已完成使用默认色。

5. **雌二醇曲线显示**：有 PK 数据时，估算卡片应显示当前值（带"~"前缀和单位）及近 48 小时曲线图，左右分别标注"48 小时前"和"现在"；无 PK 数据时，该卡片整体不显示。

6. **估算免责声明**：雌二醇卡片下方必须显示说明其为估算而非实验室检测值的文字。

7. **可操作状态限制**：只有状态为"即将到期"、"已逾期"或"待服"的第一项计划显示"记录"和"跳过"按钮；"已完成"和"窗口外记录"状态不显示按钮。

8. **记录操作流程**：点击"记录"后按钮消失、出现"正在同步…"；收到成功回调后显示"已发送"；约 1.5 秒后该条目从列表消失，同时触发快照刷新请求。

9. **跳过操作流程**：与记录操作流程相同，操作完成后该计划在后续快照中不再出现（已跳过状态）。

10. **操作失败恢复**：手机不可达时，操作后约 2 秒显示"无法连接手机"，随后按钮重新变为可用状态。

11. **撤销按钮可见性**：仅当上一次记录携带可撤销 UUID 信息时才显示"撤销记录"按钮；无可撤销信息时不显示。

12. **撤销操作流程**：点击"撤销记录"后按钮显示"正在同步…"并禁用；成功后显示"已发送"，约 1.5 秒后触发快照刷新；手机返回新快照后，被撤销记录消失，对应计划重新出现。

13. **撤销失败恢复**：手机不可达时撤销失败，按钮显示"无法连接手机"，2 秒后恢复可用。

14. **打开 App 强制刷新**：每次打开 App（onResume），无论缓存是否新鲜，都必须向手机发送快照刷新请求。

15. **跨日计划显示**：第二至五项计划中，若预定时间不在当日，应显示"MM-DD HH:mm"格式；当日计划只显示"HH:mm"。

16. **隐藏药物详情**：手机开启"隐藏药物详情"后，手表 App 所有卡片中的药名、剂量、给药途径文字应为空，仅显示组名和时间。

17. **重启后缓存持久性**：手表重启后打开 App，应立即从本地显示上次缓存的快照内容，不显示空状态，直到新快照到达。

18. **新快照清除乐观状态**：若用户已本地乐观隐藏某条目，但手机返回的新快照中该条目仍存在（例如手机未成功处理），该条目应重新出现在列表中。

19. **五项计划上限**：列表最多显示五项可快速操作的计划（DUE_SOON / OVERDUE / UPCOMING），不显示已完成计划。

20. **后台缓存刷新节奏（被动）**：无缓存时每 30 秒重试一次请求；缓存超过 30 分钟时每 5 分钟重试一次；缓存新鲜时不主动请求。
