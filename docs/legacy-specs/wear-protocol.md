# 手机-手表同步协议功能规格

## 功能名称

手机-手表同步协议（Phone-Watch Sync Protocol）

该协议定义了手机应用与 Wear OS 手表应用/Tile 之间的数据同步方式，包括手机向手表推送当前用药计划快照，以及手表向手机发送服药操作指令（记录、跳过、撤销）。协议层独立于 Android 系统 API，确保数据传输的一致性和版本兼容性。

---

## 用户入口

用户不会直接意识到该协议的存在。以下用户行为会触发协议工作：

1. 用户在手机上打开应用，手表 App 或 Tile 在后台自动请求并接收最新快照。
2. 用户在手表 App 或 Tile 上执行操作（记录服药、跳过、撤销），操作命令通过协议发送到手机。
3. 手机收到命令、完成处理后，主动将更新后的快照推送回手表。
4. 手表检测到本地缓存缺失或过期时，主动向手机请求快照刷新。

---

## 输入/输出

**手机 → 手表（快照推送）：**

手机向手表发送一份完整的"服药计划快照"，包含：

- 快照生成时刻（时间戳）
- 当前设备时区
- 今日参考日期（锚点日期）
- 今日已完成服药次数 / 今日总计划次数
- 是否隐藏药物详情（隐私模式标志）
- 应用语言标签
- 服药计划列表（最多约 64 条），每条包含：
  - 药物名称
  - 所属分组名称
  - 给药途径描述（如"口服"）
  - 剂量说明文字（如"2 mg"）
  - 计划状态（已完成 / 即将到期 / 已逾期 / 待服 / 窗口外补录）
  - 计划时间文字
  - 附加说明文字（可选）
- 血药浓度估算数据（可选），包含：
  - 当前估算值文字
  - 单位标签（如"pg/mL"）
  - 历史采样点数列（最多约 97 个点）
  - 采样间隔（分钟）
- 最近一次服药记录（可选），包含：
  - 所属分组名称
  - 药物摘要文字（如"雌二醇 · 2 mg · 口服"）
  - 记录时间文字
  - 可撤销的记录项标识列表（用于支持"撤销"操作）

**手表 → 手机（操作命令）：**

手表向手机发送以下三类命令：

- **记录服药命令**：指定目标计划分组、计划时间槽标识（可选）和计划时间。
- **跳过本次命令**：指定目标计划分组、计划时间槽标识（可选）和计划时间。
- **撤销服药命令**：指定一组已记录的服药项标识（对应最近一次记录的各条目）。

每条命令均包含一个唯一的请求 ID，供手机端去重和幂等处理。

**手表 → 手机（快照请求）：**

手表可主动向手机发送"请求刷新快照"信号，不携带业务数据，仅触发手机重新生成并推送快照。

---

## 用户操作流程

### 手表查看计划（被动同步）

1. 用户打开手表 App 或查看 Tile。
2. 若手表缓存有效（数据新鲜度未超期），直接显示缓存内容，无感知延迟。
3. 若缓存缺失或已过期，手表向手机请求快照。
4. 手机生成最新快照并推送到手表。
5. 手表收到快照后立即更新显示内容。

### 在手表上记录服药

1. 用户在手表 App 或 Tile 上点击某条计划的"记录"按钮。
2. 手表立即在本地显示操作反馈（如"已记录"提示），提供即时响应感。
3. 手表将"记录服药"命令通过协议发送到手机。
4. 手机收到命令后：验证计划时间槽是否仍有效，写入服药记录到本地数据库，更新库存、提醒和血药浓度估算。
5. 手机重新生成快照并推送回手表。
6. 手表收到新快照，刷新显示，该条计划状态更新为"已完成"。

### 在手表上跳过本次

1. 用户点击某条计划的"跳过"按钮。
2. 手表显示操作反馈。
3. "跳过"命令发送到手机。
4. 手机写入跳过记录后，推送更新快照回手表。
5. 手表刷新显示，该条计划状态更新为已跳过。

### 在手表上撤销服药

1. 用户在手表 App 上查看最近一次服药记录，点击"撤销"按钮。
2. 手表发送"撤销"命令，命令中包含所有需撤销的记录项标识。
3. 手机将对应记录从数据库中标记为已撤销，该计划恢复为待服状态。
4. 手机推送更新快照回手表，手表刷新显示。

---

## 状态变化

| 计划状态 | 用户可见含义 |
|----------|-------------|
| 待服（Upcoming） | 计划时间尚未到来，无需操作。 |
| 即将到期（Due Soon） | 计划时间即将到来，可以提前操作。 |
| 已逾期（Overdue） | 计划时间已过，尚未记录或跳过。 |
| 已完成（Done） | 已记录服药。 |
| 窗口外补录（Logged Out of Window） | 在计划窗口期外补录了服药，系统接受但标注为窗口外。 |

**快照缓存状态（手表端）：**
- 有效缓存：手表显示最新数据，Tile 刷新间隔约 30 分钟。
- 缓存缺失/过期：手表主动请求，手机推送新快照。
- 等待中：缓存请求发出但尚未收到回复，手表显示加载状态或上一次缓存内容。
- 请求失败：重试，首次重试间隔约 30 秒，之后间隔约 5 分钟。

## 数据字段的业务含义

| 字段 | 含义 |
|------|------|
| 快照生成时刻 | 手机端生成本次快照的精确时间，手表用于判断数据新鲜度。 |
| 时区 | 手机当前时区，确保手表在时区不同的环境下显示正确的本地时间。 |
| 锚点日期 | 今日日期（本地时区），用于确定"今天"的计划范围。 |
| 已完成/总计数 | 今日计划的完成进度，在手表 App 和 Tile 的摘要行显示。 |
| 隐藏药物详情 | 隐私模式：若开启，手表不显示具体药物名称和剂量，仅显示时间和状态。 |
| 应用语言标签 | 手机应用当前语言，用于手表端正确显示本地化文字。 |
| 计划时间槽标识 | 唯一标识某一计划时间槽，手表发出操作命令时携带此 ID，确保操作精确命中目标计划，而非依赖显示文字匹配。 |
| 分组标识 | 唯一标识某一药物分组，与时间槽标识配合，精确定位目标计划。 |
| 附加说明文字 | 每条计划行的补充显示文字（如已记录时显示实际记录时间与计划时间的偏差）。 |
| 血药浓度估算值文字 | 手机 PK 模型计算的当前估算值，已格式化为显示文字，含单位。 |
| 历史采样点 | 过去约 48 小时的浓度采样序列，供手表绘制浓度曲线，各点均为非负有限数值。 |
| 采样间隔 | 相邻采样点的时间间隔（分钟），手表用此重建时间轴。 |
| 最近服药摘要 | 最近一次服药的文字摘要，显示在手表 App 的"上一次服药"区域。 |
| 撤销标识列表 | 最近一次服药记录的所有组成条目的唯一 ID，供手表发出撤销命令时精确指定目标。 |
| 请求 ID | 每条操作命令的唯一 ID，手机用于幂等处理（防止网络重传造成重复记录）。 |

## 边界情况

- **手机与手表版本不同步**：协议版本化，手表解析快照时对未知字段兼容处理（较旧手表忽略较新字段），手机对旧版快照格式提供最低版本支持。命令协议只保留一个当前版本，不向后兼容旧命令格式。
- **计划时间槽在命令飞行途中被删除**：手机收到操作命令后会重新验证时间槽是否仍然有效；若已失效，操作被拒绝，手机推送最新快照告知手表当前状态。
- **操作命令重复到达（网络重传）**：手机通过请求 ID 去重，相同请求 ID 的命令只执行一次。
- **快照过大**：快照总大小有上限（约 256 KB）；计划行数最多约 64 条；血药浓度采样点最多约 97 个；字符串字段均有字节数上限。超出限制时不发送无效数据。
- **仅手表操作，手机未启动**：命令通过系统数据层传输，手机应用无需前台运行；手机 App 在后台收到命令后处理，并推送更新快照。
- **手表无血药浓度数据**：血药浓度字段为可选，手机未计算或无有效数据时不包含该字段，手表端不显示浓度区域。
- **手表无最近服药记录**：最近服药字段为可选，手机首次使用或无服药历史时不包含该字段，手表端不显示"最近服药"区域，撤销操作不可用。
- **撤销命令不含记录项**：手机拒绝接受空的撤销命令（无效请求）。

## 错误状态

- **快照请求无响应**：手表发出刷新请求后，若手机未在预期时间内响应，手表保持显示上一次缓存内容，并在界面上显示数据可能过时的提示。
- **操作命令发送失败**：若命令无法到达手机（如蓝牙断开），手表提示操作失败，用户可在手机端补充操作。
- **快照解析错误**：收到不完整或格式异常的快照数据时，手表丢弃异常数据并保留上一次有效缓存，不显示乱码或崩溃。
- **命令版本不兼容**：若手机应用版本较旧，无法识别手表发来的命令版本，操作失败，手机推送当前状态快照，手表更新显示并提示操作未能完成。

---

## 离线/重启后的行为

- **手表端缓存持久化**：快照以加密形式存储在手表本地，手表重启后无需立即联系手机即可显示上一次缓存内容。
- **手机重启后推送恢复**：手机重启后，若手表发出快照请求，手机正常处理并推送；不需要用户手动触发。
- **蓝牙断开再恢复**：连接恢复后，若手表检测到缓存过期，自动重新请求快照，无需用户干预。
- **手机离线（无网络）时**：同步协议走本地蓝牙通道（Wear Data Layer），不依赖互联网，手机离线不影响手机-手表间的直接同步。

---

## 可观察的同步行为

- 用户在手机上记录服药后，手表 App 和 Tile 的状态会在短时间内（通常数秒内）自动更新，无需用户在手表上执行任何操作。
- 用户在手表上记录服药后，手机 App 的服药列表和进度在下次打开或刷新时反映该操作。
- Tile 的数据新鲜度约为 30 分钟；超过此时间未收到新快照，Tile 会显示可能过时的提示或主动触发刷新。
- 手表 App 显示的血药浓度曲线覆盖过去约 48 小时，数据点来自手机 PK 计算结果，手表本身不重新计算。
- 手表端隐私模式（隐藏药物详情）由手机端的用户设置决定，快照中携带该标志，手表无独立设置入口。

---

## 与其他功能的关系

- **服药计划（Phone 功能）**：手表展示的所有计划数据来源于手机端的服药计划；手表不存储完整计划，仅显示快照中的有限条目（最多约 64 条，按计划时间排序，跨日不截断）。
- **血药浓度估算（PK 模型）**：手表显示的浓度值和曲线由手机端 PK 模型计算后打包进快照，手表不运行独立的计算逻辑。
- **服药记录**：手表的记录/跳过/撤销操作最终写入手机端数据库，手机是唯一事实来源；手表操作通过协议在手机端完整执行，包括库存扣减、提醒更新等联动。
- **隐私与安全**：手表只接收当前用药快照所需的最小数据集；完整的 PK 投影、血液检测记录、日记、库存详情、数据库加密密钥和备份密码均不传输到手表。手表端缓存使用 AES-256-GCM 加密，密钥存储于手表的 Android Keystore。
- **Wear OS Tile**：Tile 的快速操作（记录/跳过）和展示数据同样基于本协议的快照数据，操作同样通过本协议发送命令到手机。

## 独立实现所需的验收测试列表（描述性，不含代码）

1. **快照完整性往返**：手机生成一份包含所有字段（计划列表、血药浓度、最近服药）的快照，序列化后再反序列化，验证所有字段值与原始完全一致，无数据丢失或截断。

2. **记录服药命令往返**：构造一条"记录服药"命令（含分组 ID、时间槽 ID、计划时间），序列化后反序列化，验证所有字段还原正确；对时间槽 ID 为空的情况同样测试。

3. **撤销命令往返**：构造一条含多个记录项 ID 的"撤销"命令，序列化后反序列化，验证所有 ID 完整保留。

4. **快照版本兼容**：使用旧版本协议编码的快照，在新版协议解析器中能正常解析，新增字段使用合理默认值；不出现解析异常。

5. **非法数据拒绝**：发送包含额外尾部字节的快照负载，验证接收端拒绝解析并返回明确错误，不静默接受脏数据。

6. **计划行数上限**：尝试构造超过最大允许行数的快照，验证发送端在序列化时拒绝，不发送非法负载。

7. **负载大小上限**：尝试发送超过最大字节数的负载，验证系统拒绝并报错，不发送也不接受超大数据。

8. **手表记录后快照更新**：模拟用户在手表上点击记录，验证手机收到命令后，计划状态从"待服/逾期/即将到期"变为"已完成"；手机随即推送更新快照；手表刷新后显示该计划为已完成状态。

9. **重复命令幂等**：手表因网络波动重发相同请求 ID 的"记录服药"命令，验证手机只执行一次操作，不产生重复服药记录。

10. **悬空时间槽处理**：手机收到指向已删除或已失效计划槽位的命令，验证操作被拒绝，手机推送最新快照，手表更新显示当前实际状态（该计划不再存在）。

11. **撤销后状态恢复**：手表发出撤销命令，验证手机将对应记录撤销，该计划恢复为待服状态；手机推送更新快照，手表刷新后显示该计划为未完成。

12. **隐私模式标志传递**：手机端开启"隐藏药物详情"设置，验证生成的快照中该标志为真；手表端收到后，计划行中不显示药物名称和剂量，仅显示时间和状态。

13. **血药浓度可选字段**：手机无血药浓度数据时，生成的快照不包含该字段；手表正常解析快照，不显示浓度区域，不崩溃。

14. **手表缓存重启恢复**：手表收到并存储快照后模拟重启，验证重启后手表 App 能从本地加密缓存中恢复并展示上一次快照内容，无需再次联系手机。

15. **Tile 数据新鲜度**：Tile 显示数据超过约 30 分钟未更新，验证手表主动触发快照请求，收到新数据后 Tile 刷新显示。

16. **失败重试节奏**：手表请求快照失败，验证首次重试在约 30 秒后，后续重试间隔扩展为约 5 分钟，不出现高频无限重试。
