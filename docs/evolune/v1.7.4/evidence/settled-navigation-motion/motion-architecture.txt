v1.7.4 settled navigation motion — corrected architecture
==========================================================

New file: ui/motion/SettledGeometryPageMotion.kt
  - NavigationEdgeMotion(fromRoute, toRoute, id) — one edge per committed route change
  - NavigationEdgeMotion.crossesPrimaryChromeBoundary() — consumes the frozen
    PrimaryNavigationChrome.changes() policy (no duplicated route list)
  - RouteEdgeTracker — pure preview of the previous committed route plus an
    idempotent commit hook that advances state only after composition succeeds
  - @Composable Modifier.settledGeometryPageMotion(edge) — unchanged entrance host:
      * entranceRequired = edge.crossesPrimaryChromeBoundary()
      * pendingEntrance applies PAGE_INITIAL_SCALE / alpha 0 on the very first
        frame of the new edge (no full-size flash, no snap-down)
      * LaunchedEffect(edge.id): snapTo(initial) -> appliedEdgeId -> withFrameNanos
        (final chrome/destination layout committed) -> animateTo(1f, 220 ms)
      * same-geometry edges: inert (snap to final, no animation)

AppNavigation.kt:
  - RouteEdgeTracker is remembered once; remember(currentRoute) reads a pure
    preview, and SideEffect commits it after successful composition
  - repeated SideEffect calls for the same cached edge are no-ops
  - NavHost modifier and all four chrome-aware boundary transitions are unchanged

Chrome is NOT animated: the modifier is applied to the NavHost viewport only;
BottomNavigationBar / NavigationRailBar / AppTopBar / Scaffold / root Row are
siblings and stay at their final layout.

The frame evidence and recordings already in this directory are explicitly
pre-correction candidate evidence. No post-correction physical visual claim is
made until the pending device consent step is completed.
