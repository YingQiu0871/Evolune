Interpretation
  At B-1s, the strict-future lookup returns B, but now is still less than B.
  At B, the lookup excludes the equal candidate and returns the next daily
  occurrence, B+24h. The inclusive comparison is therefore made against B+24h,
  not against the previously observed B. The same remains true after B.

Home state consequence
  The boundary effect writes forkPointTimeHState on every row, so its displayed
  fork marker advances from B to B+24h. No row calls onRefresh; therefore
  simulationRefresh is not incremented and HRTViewModel does not publish a new
  PKState from this crossing. The existing simulationResult and its calculation
  timestamp remain the state delivered before the crossing.

Normal crossing classification
  C - never detected by the boundary predicate while enabledPlans is unchanged
  and no unrelated refresh occurs. This is a predicate failure, not an eventual
  success caused by the one-second clock.

Multiple-slot check
  A plan with slots at 08:30 and 08:35 returned 08:35 when queried exactly at
  08:30. The just-crossed first occurrence was discarded and the next remaining
  occurrence became the new comparison target.
