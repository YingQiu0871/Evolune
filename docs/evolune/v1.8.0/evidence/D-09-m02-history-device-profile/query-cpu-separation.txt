EVOLUNE v1.8.0 D-09 — QUERY VS CPU SEPARATION (MANDATORY)
=========================================================

All values are medians of measured loads (ms), n as in phase-statistics.txt.
  queryWall  = P1+P3+P4 wall (Room DAO suspension + entity->domain mapping)
  mappingCpu = caller CPU inside P3+P4 (entity -> domain conversion)
  pureCpu    = P2+P5+P6+P7 caller CPU (generation+union+projection+grouping)
  totalMain  = all caller/Main CPU of the load (mapping+pure)
  projection = P6 CPU alone (share of totalMain)

Conclusions:
1. Room queries are NOT the dominant component: at 1k/mid the query wall is
   12 ms vs 52 ms Main CPU; at 10k it is 69 ms vs 414 ms.
2. The dominant cost is the pure CPU section, and specifically the projection
   (matcher/derive): 76-94% of the Main CPU at medium and above.
3. Entity->domain mapping is small but on the caller: 1.2-18.3 ms.
4. A dispatcher boundary around the pure CPU section (generation, union,
   projection, grouping) targets 86-94% of the measured Main CPU at medium and
   above; a boundary around the queries would target the wrong component.
5. SMALL (100 events, ~1-2 months of routine use) costs 6-7 ms of projection CPU
   and is effectively negligible; the decision hinges on the MEDIUM+ results.
