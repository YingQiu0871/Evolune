# 功能规格：Google Drive 加密云端备份与同步

> 本文档从可观察的用户行为出发，描述该功能的完整规格，供独立从零实现参考。
> 文档不包含原项目源代码，不包含内部类名或私有方法名。

---

## 1. 功能名称

**Google Drive 加密云端备份与同步**

用户自愿选择的云端数据备份功能。用户的全部应用数据以用户设定的密码加密后，存储至用户自己 Google 账号的私有 Drive 应用数据目录，实现多设备数据同步与灾难恢复。

---

## 2. 用户入口

- **位置**：应用设置页面（Settings）→ 云同步（Cloud Sync）分区
- **可见性条件**：仅在通过 Google Play 分发的版本中显示该分区；通过其他渠道侧载安装的版本（非 Play 版本）不显示此分区，功能不可用
- **分区包含三个控件**：
  1. 云同步开关（带同步状态副文本，启用时显示当前同步状态与上次同步时间，禁用时显示功能简介）
  2. 同步频率选择项（仅在已启用时可操作）
  3. "立即同步"操作项（仅在已启用时可操作，副文本显示当前同步状态）

---

## 3. 输入

### 用户主动提供的输入

| 输入 | 描述 |
|------|------|
| 同步密码 | 用户首次启用时设定，需输入两次以确认；密码用于加密云端数据，最小长度有限制；密码忘记后无法恢复云端数据 |
| Google 账号授权 | 系统 OAuth 授权流程，用户同意授予应用访问其 Drive 应用数据目录的权限 |
| 同步频率 | 用户从下拉菜单选择：每天、每三天、每周、每月（30 天） |
| 冲突解决选择 | 发生数据冲突时，用户在对话框中选择"保留本地数据"或"使用云端数据" |

### 系统自动收集的输入

| 输入 | 描述 |
|------|------|
| 本地数据快照 | 应用在同步时自动读取全部用户数据并生成加密快照 |
| 网络状态 | 系统调度层检测网络连接是否可用 |
| 电量状态 | 系统调度层检测电量是否处于低电量状态 |

---

## 4. 输出

### 界面状态输出

| 状态 | 用户可见的界面变化 |
|------|-------------------|
| 未连接 | 开关显示为关闭状态；副文本显示功能简介 |
| 就绪 | 开关显示为开启；副文本显示上次同步时间 |
| 同步中 | 开关和"立即同步"项变为不可点击（灰色）；同步状态文本更新 |
| 需要授权 | 状态文本显示需要授权 |
| 冲突 | 弹出冲突解决对话框 |
| 错误 | 状态文本显示错误信息 |

### 瞬态通知输出（Toast 消息）

| 场景 | 消息含义 |
|------|----------|
| 同步成功——已上传本地数据 | 数据已成功上传至云端 |
| 同步成功——已下载云端数据 | 云端数据已成功下载并恢复至本地 |
| 同步成功——数据已是最新 | 本地与云端数据一致，无需传输 |
| 同步失败 | 同步发生错误（含授权失败、网络异常等） |
| 已断开连接 | 用户手动关闭同步功能时弹出 |
| 功能不可用 | 当前版本不支持该功能时弹出 |

### 冲突解决对话框

当同步时检测到本地数据与云端数据均有变化，且无法自动决策时，弹出模态对话框：
- **标题**：数据冲突
- **正文**：提示本地和云端数据均有修改
- **操作按钮 1**：保留本地数据（将本地数据上传覆盖云端）
- **操作按钮 2**：使用云端数据（将云端数据下载并覆盖本地，具有破坏性）

## 5. 用户操作流程

### 路径 A：手动启用与首次同步

1. 用户进入设置页面，找到云同步分区（仅 Play 版本可见）
2. 用户点击云同步开关，将其打开
3. 弹出密码设置对话框，要求用户输入并确认同步密码：
   - 密码有最小长度限制
   - 用户需在两个输入框中分别输入相同密码
   - 点击确认后对话框关闭，开始处理
4. 系统请求 Google Drive 应用数据权限：
   - 若授权结果需要用户操作（标准 OAuth 同意界面），系统弹起 Google 授权页面
   - 用户在 Google 页面确认授权
   - 授权完成后回到应用
5. 应用立即执行一次同步：
   - 读取全部本地数据并生成加密快照
   - 检查云端是否已有数据
   - 根据冲突决策逻辑执行上传或弹出冲突对话框（见第 6 节）
6. 同步完成后显示 Toast 消息，设置界面更新同步状态与上次同步时间

### 路径 B：手动触发同步

1. 用户进入设置页面，找到已启用的云同步分区
2. 点击"立即同步"
3. 开关和"立即同步"项变为不可点击（防止并发操作）
4. 系统执行与路径 A 第 5 步相同的同步逻辑
5. 完成后显示 Toast 消息，恢复可点击状态，更新状态文本

### 路径 C：自动定期同步

1. 用户设置了同步频率（每天 / 每三天 / 每周 / 每月）
2. 系统通过后台任务调度器（WorkManager）在满足以下全部条件时自动触发：
   - 设备已连接到网络
   - 电量不处于低电量状态
   - 距上次同步已达到设定间隔（间隔从调度时起算，系统可能根据省电策略延后）
3. 后台任务执行与手动同步相同的同步逻辑
4. 若同步结果为冲突，系统记录冲突状态，不弹出对话框（用户下次打开设置时可见冲突状态）
5. 若同步失败且错误为可重试类型（如网络超时），调度器自动安排重试

### 路径 D：关闭同步（断开连接）

1. 用户将云同步开关关闭
2. 系统执行以下操作：
   - 撤销应用的 Google Drive 授权
   - 删除本地存储的经 Android Keystore 包装的同步密码
   - 取消所有已排队的后台自动同步任务
   - 清除本地同步元数据（上次同步版本、内容哈希等）
3. **云端数据保留**：关闭同步不会删除 Google Drive 上已存储的加密快照
4. 显示 Toast 消息，状态更新为"未连接"

## 6. 状态变化

同步决策基于三个数据指纹（SHA-256 内容哈希）的对比：
- **本地哈希**：当前本地数据生成的内容哈希
- **云端哈希**：Google Drive 清单文件记录的上一次上传的内容哈希
- **上次同步哈希**：本设备上次同步成功时记录的内容哈希

### 场景 A：仅本地有变化

**条件**：云端哈希与上次同步哈希相同，但本地哈希与它们不同（即云端无变动，只有本地发生了修改）

**行为**：
- 将本地加密快照上传至云端
- 生成新版本号（每次上传产生唯一版本标识）
- 更新云端清单文件（新快照文件 ID、内容哈希、设备 ID、导出时间戳）
- 删除旧的云端快照文件（节省存储空间）
- 记录同步成功，更新本地同步元数据（版本号、内容哈希、同步时间）
- 显示"已上传"Toast

### 场景 B：仅云端有变化

**条件**：本地哈希与上次同步哈希相同，但云端哈希与它们不同（即本地无变动，云端由其他设备更新）

**行为**：
- 从云端下载加密快照
- 验证快照格式完整性
- 将快照解密并恢复至本地数据库（原子事务，全部成功或全部回滚）
- 记录同步成功，更新本地同步元数据
- 显示"已下载"Toast

### 场景 C：双向冲突

**条件**：本地哈希和云端哈希均与上次同步哈希不同，或本设备从未同步过但云端已有数据（上次同步哈希为空且云端已有数据）

**行为**：
1. 记录冲突状态
2. 弹出冲突解决对话框（如为后台自动同步则仅记录状态，用户下次打开设置时可见）
3. 用户选择后：
   - **保留本地**：执行场景 A 的上传流程，以本地数据覆盖云端
   - **使用云端**：执行场景 B 的下载恢复流程，以云端数据完整替换本地所有数据

**补充说明**：若云端哈希与本地哈希完全相同（无论上次同步哈希如何），系统判定数据已一致，仅更新同步时间戳，不传输数据，显示"已是最新"Toast。

## 7. 数据字段的业务含义

云端备份包含以下类别的用户数据，以加密形式存储在 Google Drive 应用数据目录。每次同步产生一个完整快照，而非增量差异。

### 7.1 备份信封元数据

| 业务含义 | 说明 |
|----------|------|
| 快照创建时间 | 本次备份的生成时刻，用于在清单中记录导出时间，不影响内容哈希的计算（内容哈希排除时间戳，保证相同数据在不同时刻导出哈希一致） |
| 应用标识符 | 标识数据来源应用，恢复时校验，不同应用的备份文件会被拒绝 |
| 快照格式版本 | 备份数据结构的版本号，用于前向/后向兼容性判断；恢复时会验证版本是否在支持范围内 |

### 7.2 应用设置

备份包含用户在设置页中配置的全部偏好，恢复后在新设备上完整复原用户个性化配置：

| 业务含义 | 说明 |
|----------|------|
| 外观主题偏好 | 深色模式选项（跟随系统 / 浅色 / 深色）、AMOLED 纯黑模式、自适应颜色 |
| 视觉辅助偏好 | 毛玻璃模糊效果、CJK 文字对齐偏移 |
| 提醒设置 | 是否启用服药提醒 |
| 显示偏好 | 是否显示已归档组的历史记录、是否隐藏参考范围、是否隐藏药物详情、每周起始日 |
| 应用锁定宽限期 | 应用锁定后无需重新认证的宽限时长选项（不包含"是否启用屏幕锁保护"本身，该设置留存在原设备） |
| 内容隐藏 | 是否在切换应用时隐藏屏幕内容 |
| 引导流程状态 | 是否已完成首次启动引导 |
| 应用语言 | 用户选择的界面语言 |
| 主界面雌二醇显示单位 | 浓度展示单位偏好 |
| 主界面 E2 图表时间窗口 | 图表显示的时间跨度选项 |
| 各指标默认单位 | 各血液检测指标的默认显示单位配置 |
| 最后记录时区 | 用户最近一次使用的时区标识 |
| 小组件外观 | 桌面小组件的主题色相、饱和度、明暗偏向、内容缩放比例、背景透明度、暗色模式 |
| 药物组名称计数器 | 新建药物组时默认名称的序号计数 |
| 库存提醒功能状态 | 库存即将不足提醒功能的开关及用户偏好 |
| 主界面卡片布局 | 主界面各功能卡片的排列顺序和隐藏状态 |

### 7.3 用户个人资料

| 业务含义 | 说明 |
|----------|------|
| 体重 | 以千克为单位存储的体重值，以及用户输入时的原始数值和单位（用于界面还原） |
| 个人资料更新时间 | 体重信息最后修改的时刻 |

### 7.4 药物目录

每个药物条目包含：

| 业务含义 | 说明 |
|----------|------|
| 药物唯一标识 | 每个药物的不可变 UUID |
| 药物来源类型 | 来自内置目录、用户自定义名称，还是从外部追踪器导入 |
| 药物名称 | 目录药物的标准名称键或用户自定义药物名称 |
| 药物类别 | 如雌激素、抗雄激素等 |
| 制剂类型 | 片剂、胶囊、单次使用注射剂、多次使用注射剂、凝胶小袋、凝胶容器、贴片等 |
| 剂量参数 | 根据制剂类型，包含每片含量(mg)、每瓶含量(mg)、浓度(mg/mL)、体积(mL)、浓度百分比、净重(g)、贴片总含量(mg)或释放速率(mcg/天) |
| 显示名称 | 用户为该药物设置的自定义显示名称 |
| 库存跟踪信息 | 是否启用库存跟踪；若启用，包括剩余单位数、上次总量、已开封容器量、低库存预警天数和库存版本号 |
| 创建/更新/归档时间 | 该药物记录的生命周期时间戳 |
| 外部导入标记 | 是否为从外部追踪器导入的记录 |

### 7.5 药物计划

每个计划组包含：

| 业务含义 | 说明 |
|----------|------|
| 计划组唯一标识 | 计划组的 UUID |
| 计划组名称与颜色 | 用于区分不同用药方案的视觉标识 |
| 提醒通知状态 | 该计划组是否启用服药提醒 |
| 周期类型 | 每天、每 N 天间隔、特定星期几、自定义 |
| 周期参数 | 间隔天数、起始日期、每周哪几天 |
| 时间槽列表 | 每个时间槽包含 UUID、时分、以及该槽的生效起始日期 |
| 药物条目列表 | 每个槽内的药物条目，包含剂量指令（整片数、片剂分数、体积毫升、重量克）和用药途径 |
| 创建/更新/归档时间 | 计划组的生命周期时间戳 |
| 是否包含过去已调度槽位 | 归档计划相关标记 |
| 计划关联关系 | 被哪个计划替换、从哪个计划创建的关联 UUID |

### 7.6 服药记录

每条服药历史记录包含：

| 业务含义 | 说明 |
|----------|------|
| 记录唯一标识 | 该服药记录的 UUID |
| 药物类别 | 记录时的药物类别（即使药物后来被修改或归档，历史类别仍保留） |
| 关联药物 | 指向药物目录的 UUID（贴片摘除记录无需关联具体药物） |
| 用药途径与剂量 | 用药方式和实际剂量（含片剂分数、体积、重量等） |
| 等效雌二醇量 | 该次服药换算为雌二醇的等效毫克量（用于 PK 模型计算，部分类型可能为空） |
| 剂量偏差 | 实际服药量与计划服药量的差值（如按计划则为空） |
| 服药时间 | 实际服药时刻（含时区信息） |
| 计划关联 | 该记录来自哪个计划组、哪个时间槽、计划时间 |
| 外部导入来源 | 从哪个外部应用导入及其外部 ID |

### 7.7 血液检测数据

**检测面板**：

| 业务含义 | 说明 |
|----------|------|
| 面板唯一标识 | 每次检测的 UUID |
| 采样时间 | 抽血时刻（含时区） |
| 备注 | 用户为该次检测添加的文字说明 |
| 距上次雌二醇用药时长 | 用于关联血药浓度趋势 |
| 距上次睾酮用药时长 | 同上 |
| 外部导入来源 | 从哪个外部工具导入 |

**检测结果**：

| 业务含义 | 说明 |
|----------|------|
| 指标标识 | 内置标准指标的键值，或用户自定义指标的 UUID |
| 检测值 | 原始数值与单位 |
| 标准化值 | 换算为系统基准单位的数值，用于不同单位间比较 |

**自定义指标定义**：

| 业务含义 | 说明 |
|----------|------|
| 自定义指标 | 用户定义的血液检测指标：缩写、名称、单位标签 |

### 7.8 日记（日期标记与笔记）

**已追踪的日期（里程碑）**：

| 业务含义 | 说明 |
|----------|------|
| 日期记录唯一标识 | 每个已追踪日期的 UUID |
| 名称 | 用户为该日期设置的标签（不能为空） |
| 图标 | 该日期的图标标识 |
| 日期 | 所标记的日历日期 |
| 调色板 | 该日期的主题色标识 |
| 英雄背景 | 该日期的背景图标标识 |
| 置顶顺序 | 若已置顶，记录排序值 |
| 创建/更新时间 | 该记录的时间戳 |

**日记笔记**：

| 业务含义 | 说明 |
|----------|------|
| 笔记唯一标识 | 每条笔记的 UUID |
| 对应日期 | 该笔记所属的日历日期（每天最多一条笔记） |
| 笔记内容 | 文字内容（不能为空） |
| 创建/更新时间 | 该笔记的时间戳 |

### 7.9 不在备份中的数据

以下数据**有意不备份**，保留在原设备：

| 数据 | 不备份原因 |
|------|-----------|
| 是否启用屏幕锁保护 | 该设置绑定设备安全环境，不应跨设备同步 |
| 同步密码本身 | 密码以 Android Keystore 加密存储，仅留在本地；上传密码会破坏加密模型 |
| 诊断日志 | 内部调试信息，不属于用户数据 |
| 库存提醒的已驳回计数 | 恢复后应在新设备上从零开始计数 |

## 8. 边界情况

| 边界情况 | 系统行为 |
|----------|----------|
| 首次在新设备启用，云端已有数据 | 由于本地是空数据库，哈希与云端不同，且没有上次同步哈希，视为冲突，弹出对话框让用户选择 |
| 首次启用，云端无数据 | 直接上传本地数据 |
| 数据未变化时触发同步 | 哈希比较后发现一致，不传输数据，仅记录同步时间，显示"已是最新" |
| 禁用同步后重新启用 | 需重新输入密码，系统立即执行一次同步；设备 ID 保留，同步历史记录（版本号、哈希）已被清除，可能触发冲突 |
| 密码错误时下载恢复 | 解密失败，同步以错误状态结束；错误信息不区分密码错误与数据损坏（防止旁路攻击） |
| Google Drive 上的文件超过大小限制（快照 128 MiB，清单 256 KiB） | 下载时拒绝超大文件，同步以错误状态结束 |
| 云端清单版本号与应用支持版本不兼容 | 同步以错误状态结束，不执行任何数据覆盖 |
| 备份快照的 JSON 版本过旧（低于最低支持版本） | 恢复被拒绝 |
| 备份快照的 JSON 版本过新（高于当前版本） | 恢复被拒绝 |
| 同步过程中应用被强制停止 | 下次启动时 WorkManager 可恢复；若为网络错误则自动重试；云端可能产生部分上传的孤立文件（旧快照文件在新版本上传成功后删除） |
| 关闭同步不删除云端数据 | 用户可通过 Google Drive 账号设置手动删除，或重新连接后以新数据覆盖 |
| 非 Play 版本（侧载 APK）尝试使用功能 | 设置页中不显示云同步分区；功能完全不可用 |
| 并发同步请求 | 系统通过内部互斥锁保证同一时刻只有一个同步操作在执行，后来的请求会等待或跳过 |

## 9. 错误状态

### 9.1 网络错误

| 错误情形 | 用户可见的表现 | 系统处理 |
|----------|--------------|---------|
| 设备无网络连接 | 后台自动同步不触发；手动触发后显示失败 Toast | WorkManager 等待网络恢复后重新调度 |
| 网络超时（连接或读取） | 显示失败 Toast | 该错误被标记为可重试类型，调度器安排自动重试 |
| Google Drive API 返回错误（非鉴权错误） | 显示失败 Toast，同步状态标记为错误 | 非可重试；用户可手动再次尝试 |
| Google Drive 文件大小超限 | 显示失败 Toast | 非可重试 |

### 9.2 低电量

| 错误情形 | 用户可见的表现 | 系统处理 |
|----------|--------------|---------|
| 设备电量过低 | 自动同步不会在低电量时触发 | WorkManager 的约束条件要求电量不低（`requiresBatteryNotLow`），低电量时任务推迟到充电后执行 |

### 9.3 数据冲突

| 错误情形 | 用户可见的表现 | 系统处理 |
|----------|--------------|---------|
| 手动同步时检测到冲突 | 立即弹出冲突解决对话框 | 等待用户选择后继续 |
| 后台自动同步时检测到冲突 | 同步状态更新为"冲突"，用户打开设置时可见；不显示 Toast | 记录冲突状态，不自动解决；用户打开设置时可手动解决 |

### 9.4 授权失败

| 错误情形 | 用户可见的表现 | 系统处理 |
|----------|--------------|---------|
| Google 授权已过期（访问令牌失效） | 同步状态更新为"需要授权"；手动触发时系统尝试刷新令牌，必要时弹出 Google 授权页面 | 令牌失效时，系统尝试清除旧令牌后重新引导用户授权 |
| 用户在 Google 授权页面取消 | 显示失败 Toast，同步未完成 | 同步以授权失败状态结束 |
| 首次启用时授权失败 | 显示失败 Toast | 功能处于启用状态但授权待完成，用户可通过"立即同步"重新触发授权流程 |
| 应用包名或签名证书不匹配 Google Cloud 配置 | 授权失败，显示错误 Toast | 非用户端可修复的配置错误 |

### 9.5 数据完整性错误

| 错误情形 | 用户可见的表现 | 系统处理 |
|----------|--------------|---------|
| 云端快照解密失败（密码错误或数据损坏） | 显示失败 Toast；不区分密码错误与数据损坏 | 同步以错误状态结束，不修改本地数据 |
| 云端快照验证失败（格式不支持、字段缺失等） | 显示失败 Toast | 同步以错误状态结束，不修改本地数据 |

## 10. 离线行为

| 场景 | 系统行为 |
|------|---------|
| 设备完全离线时触发手动同步 | 同步尝试失败，显示错误 Toast；错误被标记为可重试类型 |
| 设备离线时后台同步到期 | WorkManager 的网络约束条件不满足，任务不执行，等待网络恢复后再尝试 |
| 离线时修改本地数据 | 本地数据继续正常工作，不受影响；下次同步时将本地变化上传（若云端无变化） |
| 离线期间云端被其他设备修改 | 下次联网同步时通过哈希比较发现云端变化，执行对应决策（下载或冲突处理） |
| 切换到无 Wi-Fi 的移动数据网络 | 移动数据被视为"已连接"，WorkManager 约束仍可满足；具体调度取决于系统策略 |

**关键特性**：离线期间，本地的全部服药记录、血液检测、日记等操作均可正常进行，所有变化会在下次成功联网同步时统一同步至云端。

## 11. 重启后的行为

| 场景 | 系统行为 |
|------|---------|
| 应用启动时 | 应用启动时，同步管理器自动启动并监听同步偏好设置的变化；若同步已启用且当前版本支持该功能，则重新注册后台同步任务调度 |
| 系统重启后 | WorkManager 是 Android 系统级调度框架，设备重启后自动恢复已注册的周期性任务；无需用户重新启用 |
| 同步频率变更后重启 | 应用启动后检测到偏好设置，以最新的频率重新注册后台任务；若已有旧频率的任务，以新频率覆盖更新 |
| 后台同步任务被系统强制停止 | 若为可重试错误（如网络超时），任务会被重新调度；调度逻辑由 WorkManager 管理 |
| 本地同步状态持久化 | 同步状态（是否启用、上次同步时间、版本号、内容哈希、设备 ID、最后错误）均持久化存储，重启后完整恢复 |
| 同步密码持久化 | 同步密码以 Android Keystore 包装后存储，重启后可直接读取，无需用户重新输入密码 |

## 12. 可观察的同步行为

### 12.1 状态文本

设置页中的云同步开关下方副文本实时反映同步状态：

| 状态 | 副文本内容 |
|------|-----------|
| 功能未启用 | 显示功能简介说明文字 |
| 就绪（同步成功） | 显示上次成功同步的时间（本地时间格式） |
| 同步进行中 | 反映正在同步的状态（此时开关和同步项不可点击） |
| 需要授权 | 提示需要重新授权 |
| 冲突待解决 | 提示存在冲突需要处理 |
| 发生错误 | 显示错误信息（从存储的错误描述中读取） |

### 12.2 可观察的同步触发事件

用户可以通过以下时机观察到同步被触发：

- 首次启用同步后，立即执行一次同步
- 点击"立即同步"后，同步立即开始（界面进入不可交互状态）
- 冲突对话框中做出选择后，立即执行解决操作
- 后台自动同步完成时，若用户在设置页面则可看到同步时间更新

### 12.3 同步中的界面锁定

同步进行时：
- 云同步开关变为不可点击（防止操作被打断）
- 同步频率选择项变为不可点击
- "立即同步"项变为不可点击

操作完成（成功或失败）后，所有控件立即恢复可交互状态。

### 12.4 Toast 反馈时机

以下操作完成后显示简短 Toast（短时长）：
- 首次启用并完成初始同步
- 手动"立即同步"完成
- 冲突解决完成
- 关闭同步（显示已断开连接）
- 授权失败或功能不可用

### 12.5 设备 ID 的不可见性

每台设备在首次同步时生成唯一 ID，该 ID 写入云端清单文件，用于标识数据来源设备。用户在界面上无法直接看到此 ID，但它影响同步决策（当来自不同设备的数据产生冲突时，设备 ID 帮助系统识别数据来源）。

## 13. 与其他功能的关系

### 13.1 与本地文件备份的关系

云端同步与手动导出的本地文件备份（`.hrtbackup` 文件）使用**相同的加密格式**：
- 相同的加密算法（Argon2id 密钥派生 + AES-256-GCM 对称加密）
- 相同的数据快照结构和版本控制
- 相同的内容验证逻辑

区别在于：
- 本地备份：用户选择目录和文件名，每次生成独立文件，密码在每次导出时输入
- 云端同步：文件存储在 Google Drive 隐藏目录，密码在启用时设置一次并存储在 Android Keystore

### 13.2 与各数据模块的关系

云端备份包含的数据跨越多个功能模块：

| 功能模块 | 备份内容 |
|----------|---------|
| 药物计划 | 全部药物计划组、时间槽、每槽药物及剂量 |
| 服药记录 | 全部历史服药记录（含等效 E2 量、剂量偏差） |
| 药物目录 | 全部药物条目，含库存跟踪数据 |
| 血液检测 | 全部血检面板和结果，含自定义指标定义 |
| 日记 | 全部已追踪日期（里程碑）和日记笔记 |
| 个性化设置 | 全部用户偏好设置和个人资料（体重） |
| 桌面小组件外观 | 小组件主题色、透明度等设置 |

### 13.3 与 Android Auto Backup 的关系

应用数据库、Android Keystore 包装的同步密码、DataStore 偏好文件（含云同步配置）、以及诊断日志**均被明确排除**在系统的 Android Auto Backup 和设备转移之外，以防止敏感健康数据通过 Google 账号系统备份机制意外上传。即：Google Drive 云同步是用户主动选择的唯一云端数据通道。

### 13.4 与 Wear OS 的关系

云端同步**不涉及** Wear OS 手表端：
- 手表从手机接收快照数据，不直接访问云端
- 手表端数据（加密缓存）也不参与云备份

### 13.5 与应用锁（屏幕锁保护）的关系

当应用处于锁定状态时，即使弹出冲突对话框的条件已满足，对话框也**不会显示**（锁定状态下屏蔽所有需要用户判断的弹窗），直到用户完成生物认证/PIN 解锁后才展示。

## 14. 验收测试列表

以下测试项从用户可观察行为的角度描述，供独立实现后的验收参考。测试均以描述性文字说明前置条件、操作步骤和预期结果，不包含任何代码。

### 14.1 启用与初始同步

**T01 - 首次启用（云端无数据）**
- 前提：全新安装，云端无同步数据
- 操作：进入设置 > 开启云同步 > 输入密码并确认 > 完成 Google 授权
- 预期：立即执行同步；同步完成后 Toast 显示"已上传"；设置页显示同步就绪状态和上次同步时间；云端已有加密数据

**T02 - 首次启用（云端已有数据）**
- 前提：另一台设备已使用相同 Google 账号启用同步并上传了数据
- 操作：在新设备开启云同步 > 设置密码（与另一台设备相同）> 完成授权
- 预期：弹出冲突解决对话框；选择"使用云端数据"后，本地数据被云端数据替换；Toast 显示"已下载"

**T03 - 密码最小长度限制**
- 前提：在密码设置对话框中
- 操作：输入过短的密码，点击确认
- 预期：不接受提交，要求输入更长的密码

**T04 - 密码确认不一致**
- 前提：在密码设置对话框中
- 操作：两个密码框输入不同内容，点击确认
- 预期：不接受提交，提示两次输入不一致

### 14.2 手动同步

**T05 - 手动同步（本地有变化）**
- 前提：云同步已启用；上次同步后修改了服药记录
- 操作：点击"立即同步"
- 预期：界面进入同步中状态（不可交互）；完成后 Toast 显示"已上传"；同步时间更新

**T06 - 手动同步（云端有变化）**
- 前提：云同步已启用；另一台设备已更新并上传了新数据
- 操作：点击"立即同步"
- 预期：Toast 显示"已下载"；本地数据更新为云端最新版本

**T07 - 手动同步（无变化）**
- 前提：云同步已启用；本地和云端数据一致
- 操作：点击"立即同步"
- 预期：Toast 显示"已是最新"；同步时间更新

### 14.3 自动同步

**T08 - 自动同步调度**
- 前提：云同步已启用，频率设为"每天"
- 操作：等待超过 1 天，设备保持联网且电量充足
- 预期：应用在后台完成自动同步；用户打开设置时可看到同步时间已更新

**T09 - 低电量时不自动同步**
- 前提：云同步已启用；设备进入低电量状态
- 操作：等待自动同步时间到
- 预期：低电量时不触发自动同步；充电后恢复正常调度

**T10 - 无网络时不自动同步**
- 前提：云同步已启用；设备关闭网络
- 操作：等待自动同步时间到
- 预期：无网络时不触发自动同步；恢复网络后自动尝试

### 14.4 冲突处理

**T11 - 手动同步时的冲突对话框**
- 前提：两台设备均修改了数据后，在其中一台点击"立即同步"（另一台已先同步）
- 操作：点击"立即同步"
- 预期：弹出冲突解决对话框，包含标题、说明文字、"保留本地"和"使用云端"两个按钮

**T12 - 冲突解决：保留本地**
- 前提：冲突对话框已弹出
- 操作：点击"保留本地数据"
- 预期：本地数据上传至云端；Toast 显示"已上传"；本地数据保持不变

**T13 - 冲突解决：使用云端**
- 前提：冲突对话框已弹出
- 操作：点击"使用云端数据"
- 预期：云端数据下载并替换本地所有数据；Toast 显示"已下载"；本地数据变为云端版本

**T14 - 后台自动同步时的冲突**
- 前提：后台自动同步期间检测到冲突
- 操作：用户等待后打开设置页面
- 预期：设置页显示冲突状态；用户可通过"立即同步"触发弹出冲突对话框进行解决

### 14.5 关闭与重新连接

**T15 - 关闭同步**
- 前提：云同步已启用
- 操作：将云同步开关关闭
- 预期：Toast 显示"已断开连接"；开关显示为关闭；分区状态文本显示功能简介；自动同步任务取消；云端数据仍然保留

**T16 - 关闭后重新启用**
- 前提：之前已关闭同步
- 操作：重新开启同步开关 > 设置新密码 > 完成授权
- 预期：立即同步；若云端有上次关闭前的数据，触发冲突对话框

### 14.6 错误处理

**T17 - 密码错误时恢复失败**
- 前提：云端已有加密数据；使用错误密码尝试恢复
- 操作：在新设备启用同步并设置与云端不匹配的密码，然后在冲突对话框选择"使用云端数据"
- 预期：显示同步失败 Toast；本地数据未被修改；同步状态标记为错误

**T18 - 网络错误后自动重试**
- 前提：云同步已启用
- 操作：切断网络后点击"立即同步"
- 预期：同步失败；恢复网络后，若存在可重试的失败记录，系统在后台自动尝试

**T19 - 非 Play 版本不显示云同步分区**
- 前提：安装非 Play 渠道（侧载）版本
- 操作：打开设置页面
- 预期：设置页中不显示云同步相关分区和任何云同步入口

### 14.7 数据完整性

**T20 - 服药记录完整恢复**
- 前提：设备 A 有若干历史服药记录；云同步已启用并完成上传
- 操作：在设备 B 启用同步并使用相同密码，选择使用云端数据
- 预期：设备 B 的服药记录与设备 A 完全一致（条目数量、时间、药物、剂量均匹配）

**T21 - 应用设置完整恢复**
- 前提：设备 A 设置了特定语言和深色模式；云同步上传了此设置
- 操作：在设备 B 完成云端数据恢复
- 预期：设备 B 的语言、深色模式与设备 A 一致；屏幕锁保护状态保持设备 B 原有设置（不被覆盖）

**T22 - 日记数据完整恢复**
- 前提：设备 A 有已追踪日期和日记笔记
- 操作：在设备 B 恢复云端数据
- 预期：所有已追踪日期（含图标、调色板、置顶状态）和日记笔记完整出现在设备 B

**T23 - 血液检测数据完整恢复**
- 前提：设备 A 有多次血液检测记录，含自定义指标
- 操作：在设备 B 恢复云端数据
- 预期：所有血检面板、检测结果和自定义指标定义完整出现在设备 B

### 14.8 同步频率

**T24 - 同步频率选项完整性**
- 操作：开启云同步后，点击同步频率项
- 预期：弹出下拉菜单，包含且仅包含以下选项：每天、每三天、每周、每月（30 天）

**T25 - 同步频率更改立即生效**
- 前提：当前频率为"每周"
- 操作：将频率更改为"每天"
- 预期：后台调度任务以新频率重新注册；原来的每周任务被替换
