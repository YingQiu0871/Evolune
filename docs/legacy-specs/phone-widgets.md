# 规格说明：手机桌面小组件

**功能代号：** 手机桌面小组件
**文档用途：** 基于可观察产品行为的独立实现规格，不包含任何原项目源代码
**目标读者：** 从未接触过原项目代码的开发者

---

## 1. 功能名称

**手机桌面小组件**

允许用户在 Android 桌面（Home Screen）直接查看当日服药计划进度、快速记录服药，以及导航至应用内对应条目。该功能由两种尺寸规格组成：

- **中型小组件**（默认 2×2 网格单元）：显示今日完成进度和下一项待处理剂量。
- **大型小组件**（默认 4×2 网格单元，可缩小至 3×2）：显示今日完成进度、雌二醇估算值，以及按时段分组的完整服药列表。

---

## 2. 用户入口

### 2.1 添加小组件
用户通过 Android 启动器的小组件选择器（长按桌面 → 小组件）找到应用并选择所需尺寸，拖拽到桌面放置。

### 2.2 选择器预览
- 在选择器中，每种小组件尺寸均展示一个预览画面，包含示例数据（非真实用户数据）。
- Android 12 及以下：展示静态 XML 预览布局，包含硬编码示例字符串。
- Android 15 及以上：展示动态生成的 Compose 渲染预览，样式与实际小组件一致。

### 2.3 重新配置（API 31+）
在 Android 12 及以上系统中，用户可长按已放置的小组件，选择"重新配置"以打开外观设置界面。API 31 以下系统的启动器菜单中不显示此入口。

---

## 3. 输入：各尺寸小组件的数据来源

两种小组件均从一个持久化的本地快照读取数据。该快照由应用在后台维护，并在以下数据变化时自动更新：

| 触发源 | 说明 |
|---|---|
| 今日服药计划变化 | 新增/修改/删除药物组、计划或记录 |
| 相关设置变化 | 隐藏药物详情、自适应颜色、E2 显示单位、应用语言、显示已归档组记录 |
| 外观设置变化 | 强调色、饱和度、明暗深度、内容缩放、背景透明度、深色模式 |
| 每 15 分钟周期性检查 | 检测快照时效性、状态过渡（如 UPCOMING 变为 DUE_SOON） |
| 设备日期/时间/时区变化 | 包含 BOOT_COMPLETED、ACTION_DATE_CHANGED、ACTION_TIME_CHANGED、ACTION_TIMEZONE_CHANGED |
| 午夜精确闹钟 | 每日跨天时触发 |
| 12/24 小时制偏好切换 | 时间字符串已在快照中预格式化，切换时重建 |

快照内容涵盖：

- 今日已完成剂量数（doneCount）与计划总数（totalCount）
- 手动记录数（manualCount）
- 是否存在活跃药物组
- 是否隐藏药物详情
- 各服药行的完整信息（见第 7 节）
- PK 投影数据（用于 E2 估算趋势）
- E2 显示单位
- 应用语言标签

---

## 4. 输出：用户在桌面看到的内容

### 4.1 中型小组件（2×2）

整体布局从上到下分为两个区域：

**顶部区域（进度）：**
- 左侧：大写"TODAY"标签
- 右侧（当 E2 估算可用时）：雌二醇估算趋势文字，格式如"E2 ~120 pg/mL"
- 下方：大号数字显示已完成数量，旁边附加后缀（如"/ 3 DONE"或手动计数）
- 右侧（当存在计划时）：圆形进度环，与完成比例对应

**底部区域（下一剂量/完成状态）：**
根据当前状态显示以下内容之一：

- **存在待处理剂量：** 显示一张卡片，包含彩色纵向强调条、药物名称、给药途径和剂量（可配置隐藏）、右侧计划时间文字和操作按钮
- **所有剂量均已在窗口内完成（完美依从）：** 居中显示彩色图标徽章 + "ALL DONE" 文字
- **所有剂量均已记录但部分超出时间窗口：** 居中显示徽章 + "ALL LOGGED" 文字
- **今日无计划安排：** 居中显示徽章 + "NO DOSES TODAY" 文字
- **已无可操作剂量（部分错过）：** 居中显示徽章 + "NOTHING MORE TODAY" 文字

### 4.2 大型小组件（4×2 / 3×2）

**顶部区域（摘要行）：**
- 左侧：大写"TODAY"标签，加上计数摘要（如"TODAY · 1 / 3 DONE"）
- 右侧（当 E2 估算可用时）：E2 估算趋势文字，宽度固定（使用透明占位文字保持布局稳定）
- 下方（当存在计划时）：水平进度条，每格代表一个计划剂量槽，已完成格填充，未完成格显示轨道色

**中央区域（服药列表）：**
可纵向滚动的列表，按以下时段分组，有数据的时段才显示对应标题：

| 分组标题 | 包含内容 |
|---|---|
| LAST NIGHT | 前一日下午 6 点之后、当日凌晨 6 点之前的未完成剂量（当前时间早于早 6 点时展示） |
| TODAY | 今日计划的服药行 |
| TONIGHT | 今晚至明日凌晨 6 点的即将到来剂量（当前时间晚于下午 6 点时展示） |

每行服药条目包含：彩色纵向强调条、药物名称（可配置隐藏详情时显示组名）、给药途径和剂量（可配置隐藏）、尾部时间或状态标签、操作按钮。

**今日无计划时：** 列表区域替换为居中图标徽章 + "NO DOSES TODAY" 文字。

## 5. 用户操作流程

### 5.1 添加小组件
1. 用户长按桌面空白区域，进入启动器编辑模式。
2. 点击"小组件"，找到应用，展开后选择"中型"或"大型"。
3. 拖拽到目标位置，松手放置。
4. 在 API 31+ 设备上，放置后自动弹出外观设置界面（可选，用户也可取消）。若取消，小组件保持默认外观正常显示。

### 5.2 快速记录服药
1. 当某个剂量行处于"即将到期"（DUE_SOON）或"已过期"（OVERDUE）状态时，该行右侧显示可点击的记录按钮（"+"图标）。
2. 用户点击该按钮，应用在后台记录服药，无需打开应用主界面。
3. 若同一计划槽包含多个药物，点击后一次性记录该槽的所有药物。
4. 记录成功后，小组件自动刷新，对应行变为"已完成"（DONE）状态。
5. 如果触发了库存预警，用户会看到一条 Toast 提示（低库存警告），与在应用内记录效果相同。

### 5.3 导航至应用内对应行
1. 点击剂量行的主体区域（非按钮区），应用以单顶（single-top）模式启动并滚动至对应计划行，同时高亮闪烁该行。
2. 手动记录行通过记录 UUID 定位；计划行通过"组 UUID + 时间槽 UUID + 计划时间 + 药物 UUID"组合定位。

### 5.4 点击小组件背景
点击小组件中任何未被行点击消费的区域，均打开应用主界面首页。

### 5.5 调整小组件尺寸
1. 长按小组件进入拖动/调整模式。
2. 中型小组件支持水平和垂直方向调整，最小值为 110×80 dp（对应 2×2 格）。
3. 大型小组件支持水平和垂直方向调整，默认 4×2，最小可缩至 3×2（minResize 140×80 dp）。
4. 宽度缩小至 260 dp 以下时，大型小组件进入紧凑布局（分组标题减少间距）。
5. 调整尺寸的过程中和之后，小组件以新尺寸重新渲染，圆角形状保持不变。

### 5.6 外观设置（API 31+）
1. 长按已放置的小组件，选择"重新配置"。
2. 进入全屏外观设置界面，背景透出系统壁纸。
3. 界面上方显示实时预览，下方展示各配置控制项：
   - 深色模式：跟随系统 / 强制浅色 / 强制深色
   - 内容缩放
   - 背景透明度
   - 强调色（色相选择器；留空则使用系统 Material You 动态调色板，API 31+ 启用动态色时）
   - 饱和度
   - 明暗深度（light balance）
4. 预览区角落有一个按钮，可临时切换预览的深浅色，不影响已保存值。
5. 点击"保存"，配置生效；点击取消或返回，配置不保存。

## 6. 状态变化

### 6.1 服药行状态及可观察外观

| 状态 | 触发条件 | 操作按钮外观 | 按钮是否可点击 |
|---|---|---|---|
| UPCOMING（即将到来） | 剂量尚在时间窗口之前 | 圆形胶囊，控制色背景，箭头图标 | 点击导航至应用（非记录） |
| DUE_SOON（即将到期） | 剂量进入时间窗口、尚未记录 | 圆形胶囊，主色背景，"+"图标 | 可点击快速记录 |
| OVERDUE（已过期） | 超过时间窗口 1 小时宽限期仍未记录 | 圆形胶囊，控制色背景（较暗），"+"图标 | 可点击（记录为超窗口条目） |
| DONE（已完成） | 在时间窗口内记录了服药 | 圆形胶囊，主色容器背景，勾选图标 | 不可点击（仅展示） |
| LOGGED_OUT_OF_WINDOW（超窗口已记录） | 在窗口之外记录了服药 | 圆形胶囊，控制色背景，勾选图标（较暗） | 不可点击（仅展示） |

### 6.2 当日无计划

- 今日没有任何计划安排，且没有前晚结转行和今晚预告行时，两种小组件均显示"NO DOSES TODAY"空状态徽章。
- 这与"所有剂量已完成"是不同状态：无计划时徽章使用主色背景（庆祝色），已完成时同样使用主色背景。

### 6.3 所有剂量均已处理

- **所有剂量均在时间窗口内完成（DONE）：** 中型小组件底部显示"ALL DONE"，使用庆祝色徽章。
- **所有剂量均已记录但至少一条超出时间窗口（无遗漏槽）：** 显示"ALL LOGGED"，使用普通色徽章。
- **存在至少一条 OVERDUE（有遗漏）且无其他可操作行：** 显示"NOTHING MORE TODAY"，使用普通色徽章。

### 6.4 已归档组的剂量行

- 已归档药物组中未完成的剂量仍会在小组件上显示，行末尾有档案箱图标标识。
- 这类行同样可以快速记录，但应用会在实际记录前验证该组是否仍处于归档状态；若状态已变，则刷新小组件而不写入记录。

### 6.5 手动记录行

- 非计划（手动）记录在大型小组件的今日区域以独立行展示，行末尾有编辑图标。
- 启用"隐藏药物详情"时，手动记录显示为"MANUAL RECORD"文字，不显示时间标签。
- 手动记录行不参与中型小组件底部卡片的剂量选择逻辑。

### 6.6 前晚结转与今晚预告

- **前晚结转（LAST NIGHT）：** 在凌晨 6 点之前，前一日下午 6 点以后的未完成剂量以"LAST NIGHT"分组出现在大型小组件顶部，并且这些行也参与中型小组件底部卡片的显示（eligible for active row）。在早 6 点之后，此分组消失。
- **今晚预告（TONIGHT）：** 在下午 6 点之后，明日凌晨 6 点前的计划剂量以"TONIGHT"分组出现在大型小组件底部。这些行不参与中型小组件底部卡片的选择，但如果当前无其他 DUE_SOON/OVERDUE/UPCOMING 行，中型小组件底部可显示第一条 COMING_UP 行。

## 7. 数据字段的业务含义

| 字段 | 业务含义 |
|---|---|
| doneCount | 今日已在时间窗口内完成记录的计划剂量数量（DONE 状态） |
| totalCount | 今日全部计划剂量槽的数量（不含手动记录和前晚/今晚行） |
| manualCount | 今日手动（非计划）记录的数量 |
| hasActiveGroups | 是否存在至少一个活跃（未归档）药物组；控制空状态显示 |
| hideMedicationDetails | 用户是否开启了隐藏药物详情的隐私选项；开启时只显示组名而非具体药物名 |
| 服药行 - groupName | 药物组的用户可见名称（例如"雌二醇"） |
| 服药行 - medicationName | 具体药物名（例如"戊酸雌二醇"）；hideMedicationDetails 开启时不显示 |
| 服药行 - routeLabel | 给药途径标签（例如"口服"）；hideMedicationDetails 开启时不显示 |
| 服药行 - doseText | 剂量文字（例如"2 mg"）；hideMedicationDetails 开启时不显示 |
| 服药行 - status | 当前剂量行的状态：DONE / DUE_SOON / OVERDUE / UPCOMING / LOGGED_OUT_OF_WINDOW |
| 服药行 - scheduledAt | 该剂量槽的计划时间，用于时段分组和排序 |
| 服药行 - trailingText | 尾部文字：通常是预格式化的计划时间字符串；DONE/LOGGED_OUT_OF_WINDOW 无尾部文字 |
| 服药行 - contextChip | 时段标记：null（今日）、LAST_NIGHT（前晚结转）、COMING_UP（今晚预告） |
| 服药行 - colorKey | 药物组的强调色键值，用于呈现纵向彩色强调条 |
| 服药行 - isManualRecord | 是否为手动（非计划）记录；影响图标、导航方式和分组行为 |
| 服药行 - isFromArchivedGroup | 是否来自已归档的药物组；影响尾部图标（档案箱）和快速记录校验逻辑 |
| 服药行 - entryUuid | 手动记录的唯一 ID，用于导航定位；计划行为 null |
| 服药行 - groupUuid | 药物组的唯一标识符；用于分组折叠和快速记录操作目标 |
| 服药行 - scheduleTimeUuid | 计划时间槽的唯一标识符；与 groupUuid 共同构成折叠键 |
| 服药行 - medicationUuid | 单个药物槽的标识符；单药物场景用于精确导航；折叠后的组行此字段为 null |
| pkProjection | PK 药代动力学投影数据，用于计算 E2 估算趋势；可为 null（无 PK 数据时不显示 E2 区域） |
| e2DisplayUnit | E2 显示单位（如 pg/mL），影响趋势文字格式 |

## 8. 边界情况

### 8.1 最小尺寸

- **中型小组件：** minResizeWidth = 110 dp，minResizeHeight = 80 dp。小于此尺寸，启动器不允许继续缩小。
- **大型小组件：** minResizeWidth = 140 dp，minResizeHeight = 80 dp，对应 3×2 最小格数。

### 8.2 260 dp 宽度阈值

大型小组件宽度小于 260 dp 时，进入紧凑布局：分组标题（LAST NIGHT / TODAY / TONIGHT）的顶部间距减小，使内容在较窄空间内仍可正常显示。其他布局和字体大小不受此阈值影响（仍由基准缩放控制）。

### 8.3 无数据（首次安装 / 数据未就绪）

- 应用首次安装后尚未添加任何药物组时，或快照尚未生成时，两种小组件均显示空状态：居中图标徽章 + "No medications" 文字。
- 空状态定义为：快照不存在，或快照存在但既无活跃药物组、也无服药行。

### 8.4 schema 版本不匹配

持久化快照包含一个 schema 版本号。若读取到的快照版本与当前应用不匹配，该快照被视为无效并忽略，小组件显示空状态，直到应用重新生成有效快照。

### 8.5 设备基准尺寸

不同设备和启动器对同一网格单元分配的 dp 尺寸不同。小组件在首次渲染时捕获设备基准高度（竖屏目标单元高度），并永久保存，后续尺寸调整不会改变内容的视觉缩放比例，只改变容器大小。首次渲染前（高度报告值超出合理范围 50–400 dp），使用参考基准值（276 dp）进行缩放（scale = 1.0）。

### 8.6 同组多药物折叠

- 中型小组件：同一计划槽的多药物行始终折叠为一行，显示组名，操作按钮记录整组。
- 大型小组件：开启"隐藏药物详情"时同样折叠，折叠行名称格式为"组名 · 数量"（如"雌二醇 · 2"）；未开启时每个药物单独显示一行。

### 8.7 同名不同组

折叠以 groupUuid（非 groupName）为键，确保恰好同名但不同组的情况不会错误折叠。

### 8.8 空白 trailingText 的保留节点

在技术实现上，即使尾部文字为空，其对应的 UI 节点也必须始终保留在视图树中（以空字符串渲染），以保证视图树结构稳定——这是 Android 小组件远程视图复用机制的要求，隐私模式切换不能引起树结构变化。

## 9. 错误状态

### 9.1 快照文件损坏

若持久化快照文件无法正常读取（如解密失败或文件损坏），应用会将存储重置为空状态，不崩溃。小组件随即显示空状态（"No medications"），并在应用下次生成有效快照后自动恢复正常显示。

### 9.2 快速记录失败

快速记录是后台异步操作。若操作失败（进程被终止、存储错误等），用户不会收到明确的错误提示，但小组件不会更新为已完成状态——下次快照刷新时仍显示原状态。这是已知权衡，源于 Android 小组件的 PendingIntent 执行机制限制。

### 9.3 归档组记录过期

若用户点击某个已归档组的剂量行的记录按钮，但在按下按钮和实际处理之间该组的状态发生变化（如从归档变回活跃），应用会刷新小组件并放弃此次记录，而不写入错误数据。

### 9.4 选项尚未报告

在首次放置小组件时，启动器可能尚未报告实际单元尺寸。此时小组件以参考基准（276 dp）渲染，外观正常；待启动器报告真实尺寸后，小组件重新以正确基准渲染。

---

## 10. 离线行为

- 小组件完全基于本地存储（加密持久化快照）运行，不依赖网络。
- 无网络时，显示内容与联网时完全相同，显示最后一次成功写入的快照数据。
- 快速记录操作同样在本地完成，不需要网络连接。
- E2 估算趋势文字基于已记录的本地数据计算，无需联网。

## 11. 重启后的行为

### 11.1 快照数据

小组件使用的快照数据（服药行、计数等）不包含在系统备份或设备迁移中，被视为派生状态。设备重启后，应用在后台启动时会从主数据库重新构建快照。在重建完成之前，小组件可能短暂显示空状态或上次的快照内容。

### 11.2 外观设置

外观设置（默认外观）会随 Android Auto Backup 备份和恢复。迁移到新设备后，小组件的颜色、透明度等设置会被恢复，而服药数据快照会在应用首次启动后重建。

### 11.3 午夜闹钟

设备重启会清除已注册的精确午夜闹钟。应用在接收到 BOOT_COMPLETED 广播时，会立即重新注册午夜闹钟，并触发一次数据刷新，确保跨天逻辑正确执行。

### 11.4 设备基准高度

首次渲染时捕获的设备基准高度存储在设备本地 SharedPreferences 中（不随备份恢复）。迁移到新设备后，基准高度会在新设备首次渲染小组件时重新捕获。

## 12. 可观察的视觉规格

### 12.1 整体形状与圆角

| 区域 | 圆角半径 |
|---|---|
| 小组件外壳（Shell） | 22 dp |
| 服药卡片（Card） | 10 dp |
| 圆形按钮/徽章（Pill） | 全圆（999 dp） |

圆角通过预渲染位图蒙版实现，而非依赖启动器的 outline clipping。这确保在启动器进行拖动、移动或调整尺寸时，圆角形状始终保持正确，不会因启动器临时禁用 View outline clipping 而变方。

### 12.2 颜色体系

颜色由以下来源之一确定（优先级从高到低）：

1. 用户在外观设置中选择的明确色相（seedHue）
2. API 31+ 且启用自适应颜色时的系统 Material You 动态调色板
3. 应用内置的默认种子色

颜色在 HCT 色彩空间中派生，饱和度参数影响色度，明暗深度参数影响色调深度。

### 12.3 进度组件

- **进度条（大型小组件）：** 水平方向，每个计划槽对应一个独立的胶囊形色块，已完成者显示主色，未完成者显示轮廓色。色块之间有 3 dp 间距，高度约 6 dp（按比例缩放）。
- **进度环（中型小组件）：** 圆形，每个计划槽对应一段圆弧，已完成段填充主色，未完成段为轮廓色。仅有一个槽时显示完整圆环；多个槽时分段，各段之间有间隙（圆端头不相邻）。

### 12.4 服药行卡片

- 高度：约 64 dp（按设备基准比例缩放）
- 左侧强调条：宽约 6 dp，高约 44 dp，药物组对应的强调色，圆角胶囊形
- 药物名字体大小：约 18 sp（按比例缩放），中等字重
- 给药途径/剂量文字：约 14 sp（按比例缩放），普通字重，次级颜色
- 操作按钮区域：约 32–44 dp（圆形胶囊，不同状态略有差异）

### 12.5 紧凑布局阈值

大型小组件宽度 < 260 dp 时：分组标题的 E2 文字与进度条之间的间距从 48 dp 减少至约 10 dp（按比例缩放），其余布局不变。

### 12.6 内容缩放

内容缩放通过设备基准高度 / 参考基准高度（276 dp）的比值确定，在用户选择的内容缩放系数上再叠加。所有字号、间距、图标尺寸均等比缩放。基准高度比值有一个最小下限（约 0.35），防止极端情况下内容不可读。

### 12.7 深色模式

- **跟随系统：** 小组件颜色随系统深浅模式切换。位图图标通过 ColorFilter 着色，不预烘焙颜色，确保深浅色均正确显示。
- **强制深色 / 强制浅色：** 无论系统设置如何，始终以指定深浅色渲染。

### 12.8 选择器预览尺寸

| 小组件尺寸 | 预览画布尺寸（dp） | 内容缩放 |
|---|---|---|
| 中型（2×2） | 306 × 276 | 0.6（相对参考基准缩小） |
| 大型（4×2） | 624 × 276 | 0.6（相对参考基准缩小） |

## 13. 与其他功能的关系

### 13.1 药物计划与记录（核心数据源）
小组件的所有显示内容均派生自本地服药计划和记录数据。计划的新增、修改、删除，以及服药记录的写入（含撤销），均会触发小组件快照的重建与刷新。小组件不重新运行剂量计算逻辑，而是消费应用主模块已计算好的今日计划快照。

### 13.2 快速记录与库存追踪
通过小组件快速记录的服药与在应用内记录效果完全一致：库存数量同步扣减（针对开启库存追踪的药物），并在触发低库存阈值时显示与应用内相同的 Toast 提示。

### 13.3 PK 血药浓度估算
当 PK 模型的投影数据有效时（药物和记录满足 PK 建模条件），两种小组件均可在顶部区域显示当前雌二醇估算趋势文字（如"E2 ~120 pg/mL"）。此字段可为空（无 PK 数据时不显示）。小组件不独立运行 PK 计算，而是读取应用预计算并写入快照的投影结果。

### 13.4 设置
以下设置项会直接影响小组件显示，变更时触发快照重建：
- **隐藏药物详情（Hide Medication Details）：** 开启后，所有行显示组名而非药物名，不显示给药途径和剂量，手动记录显示为"MANUAL RECORD"。
- **E2 显示单位（E2 Display Unit）：** 影响趋势文字中的单位标签（如 pg/mL 或 pmol/L）。
- **应用语言（App Language）：** 小组件中所有可翻译字符串（TODAY、LAST NIGHT、DONE 等）随应用语言设置变化，与系统语言解耦。
- **显示已归档组记录（Show Archived Group Records）：** 控制已归档组的未完成剂量是否出现在小组件列表中。
- **自适应颜色（Adaptive Color）：** 控制是否使用系统 Material You 动态调色板（API 31+ 有效）。

### 13.5 应用主界面高亮导航
点击小组件中的剂量行（非按钮区域），会在打开应用主界面时附带一个"高亮"请求，使主界面自动滚动至对应条目并短暂闪烁高亮。手动记录行通过 entry UUID 定位，计划行通过 group UUID + 时间槽 UUID + 计划时间 + 药物 UUID 的组合定位。

### 13.6 Anchor/Tracked Date 小组件（分离功能）
应用还包含一种 Anchor 小组件（追踪日期小组件，2×1），显示一个记录日期（锚点）及其经过天数。该小组件与本文档描述的服药剂量小组件完全独立：它读取日记/锚点数据而非服药计划快照，有独立的数据管道和管理器。两者共享外观设置存储（颜色、透明度等），但数据逻辑互不干扰。

## 14. 独立实现的验收测试列表

以下测试描述用户可观察的行为，不包含任何代码。实现者应根据自身架构设计对应测试。

### T01 - 空状态显示
**前提：** 应用已安装，未添加任何药物组。
**操作：** 从选择器添加中型或大型小组件到桌面。
**预期：** 小组件显示一个居中图标徽章，下方文字为"No medications"（或对应翻译）。

### T02 - 今日有计划时的进度显示（中型）
**前提：** 今日有 3 个计划剂量，已完成 1 个。
**操作：** 查看中型小组件。
**预期：** 顶部显示"TODAY"，大号数字显示"1"，后跟"/ 3 DONE"（或类似格式），右侧显示 3 段进度环，1 段为主色，2 段为轨道色。

### T03 - 今日有计划时的进度显示（大型）
**前提：** 今日有 3 个计划剂量，已完成 1 个。
**操作：** 查看大型小组件。
**预期：** 顶部显示"TODAY · 1 / 3 DONE"（或类似格式），下方进度条显示 3 段，1 段为主色。

### T04 - DUE_SOON 状态行的快速记录
**前提：** 某个剂量槽进入时间窗口（DUE_SOON 状态）。
**操作：** 点击该行右侧的"+"按钮。
**预期：** 无需打开应用，小组件刷新后该行状态变为 DONE（勾选图标），完成计数加 1。

### T05 - OVERDUE 状态行的可点击性
**前提：** 某个剂量槽超过时间窗口（OVERDUE 状态）。
**操作：** 查看该行按钮样式，然后点击。
**预期：** 按钮显示为控制色（较暗）背景的"+"图标，点击后成功记录，行变为 LOGGED_OUT_OF_WINDOW 状态（带较暗勾选图标）。

### T06 - UPCOMING 状态行的按钮不可记录
**前提：** 某个剂量槽尚未进入时间窗口（UPCOMING 状态）。
**操作：** 查看并点击右侧按钮。
**预期：** 按钮为箭头图标（导航型），点击后打开应用并导航至对应行，不触发快速记录。

### T07 - DONE 状态行无可点击按钮
**前提：** 某个剂量槽已在窗口内完成记录（DONE 状态）。
**操作：** 查看并尝试点击右侧按钮。
**预期：** 按钮显示勾选图标（主色容器背景），不可点击。

### T08 - 所有剂量完成后的徽章（中型）
**前提：** 今日所有计划剂量均已在时间窗口内完成。
**操作：** 查看中型小组件底部区域。
**预期：** 显示"ALL DONE"文字及庆祝色徽章，无剂量卡片。

### T09 - 今日无计划的空状态徽章
**前提：** 有活跃药物组，但今日没有任何计划剂量。
**操作：** 查看中型或大型小组件。
**预期：** 显示"NO DOSES TODAY"文字及图标徽章。

### T10 - 大型小组件的分组显示
**前提：** 今日有计划剂量；时间在凌晨 6 点之后、下午 6 点之前。
**操作：** 查看大型小组件。
**预期：** 仅显示"TODAY"分组（无 LAST NIGHT、无 TONIGHT），列表按 scheduledAt 排序。

### T11 - 前晚结转（LAST NIGHT 分组）
**前提：** 当前时间在凌晨 6 点之前；前一日下午 6 点后有未完成剂量。
**操作：** 查看大型小组件。
**预期：** 列表顶部出现"LAST NIGHT"分组标题，结转行在其下方；"TODAY"分组在其后（若今日有行）。

### T12 - 今晚预告（TONIGHT 分组）
**前提：** 当前时间在下午 6 点之后；明日凌晨 6 点前有计划剂量。
**操作：** 查看大型小组件。
**预期：** 列表底部出现"TONIGHT"分组标题，明日早期行在其下方。

### T13 - 尺寸调整后内容视觉比例不变
**前提：** 大型小组件已放置，内容正常显示。
**操作：** 长按小组件，缩小宽度至接近最小值（约 3×2）。
**预期：** 小组件容器缩小，但内容的字体大小和图标大小保持不变（视觉比例与初始放置时相同）；圆角形状保持圆润。

### T14 - 260 dp 紧凑布局
**前提：** 大型小组件已放置，宽度调整至 260 dp 以下。
**操作：** 查看分组标题区域。
**预期：** 顶部区域中标题标签与 E2 文字之间的间距明显减小（紧凑）。

### T15 - 行点击导航至应用内对应行
**前提：** 小组件中存在一个计划剂量行。
**操作：** 点击该行主体（非按钮区域）。
**预期：** 应用主界面打开，并自动滚动至该剂量对应的计划行，该行短暂高亮闪烁。

### T16 - 隐藏药物详情模式
**前提：** 应用内开启"隐藏药物详情"设置。
**操作：** 查看大型小组件中的服药行。
**预期：** 每行显示药物组名而非具体药物名，不显示给药途径和剂量文字。手动记录行显示"MANUAL RECORD"。

### T17 - 应用语言切换
**前提：** 应用语言设置为非系统语言（如中文）。
**操作：** 查看小组件中的标签文字（TODAY、LAST NIGHT、DONE 等）。
**预期：** 这些标签以应用语言显示，与系统语言无关。

### T18 - 12/24 小时制切换
**前提：** 小组件中有剂量行显示时间（trailingText）。
**操作：** 在系统设置中切换 12/24 小时制。
**预期：** 小组件在不重新打开应用的情况下，时间显示格式自动更新为新格式。

### T19 - 外观设置实时预览（API 31+）
**前提：** 设备为 API 31+，小组件已放置。
**操作：** 长按小组件 → 重新配置 → 在外观设置界面调整强调色。
**预期：** 预览画面即时反映颜色变化；保存后，桌面上的小组件同步更新为新外观。

### T20 - 已归档组剂量行标识
**前提：** 存在一个已归档的药物组，其中有未完成剂量（且"显示已归档组记录"已开启）。
**操作：** 查看大型小组件的剂量列表。
**预期：** 该组的剂量行末尾显示档案箱图标（归档标识），且该行同样可以点击记录。

### T21 - 设备重启后快照恢复
**前提：** 小组件已放置，数据正常显示。
**操作：** 重启设备。
**预期：** 启动器显示后，应用后台启动并在短时间内重建快照，小组件恢复显示正确的服药计划数据；小组件不会永久停留在空状态。

### T22 - 同一计划槽多药物折叠（中型）
**前提：** 同一计划时间有 2 个药物需要服用（属于同一药物组）。
**操作：** 查看中型小组件底部的剂量卡片。
**预期：** 显示为一张卡片，名称为组名，点击"+"按钮一次性记录两个药物。

### T23 - E2 估算趋势显示
**前提：** 已有足够的记录数据支持 PK 估算，E2 显示单位为 pg/mL。
**操作：** 查看中型或大型小组件顶部区域。
**预期：** 顶部右侧显示类似"E2 ~120 pg/mL"格式的文字。

### T24 - 无 PK 数据时不显示 E2 区域
**前提：** 无足够数据支持 PK 估算（或所用药物无 PK 模型）。
**操作：** 查看小组件顶部区域。
**预期：** 不显示 E2 估算文字，顶部区域不出现对应占位空间。

### T25 - schema 版本不匹配后的恢复
**前提：** 模拟持久化快照 schema 版本过期（如通过覆盖安装降版本）。
**操作：** 打开应用后查看小组件。
**预期：** 小组件先短暂显示空状态，应用成功生成新版本快照后自动恢复正常显示数据。
