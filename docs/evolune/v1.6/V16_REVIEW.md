# Evolune v1.6 — 审阅方式与验收门槛

状态：`DONE / FINAL APPROVE`。A–G 已完成；负责人真实手表验收、签名候选覆盖安装、
独立最终技术复审和发布门禁均通过。实施目标见 [V16_PLAN.md](V16_PLAN.md)。

## 每阶段审阅流程

1. 实施者提交一个完整可审阅批次：目标、起点与候选提交、变更列表、测试证据、截图/测量及已知问题。
2. 独立审阅者以确切 diff 和相关调用链核对实现，选择关键测试独立重跑；
   审阅过程中保持只读，以具体失败路径提出问题，不仅复述实施报告。
3. 产品/视觉审阅依据真实 launcher、Tile 或表盘证据检查信息、交互和可读性；
   由项目负责人或其指定审阅者给出结论，自动化不能代替视觉结论。
4. 实施者修复问题并提供新提交；审阅者复核修复与受影响回归。
5. 技术与必要的产品审阅均通过、证据齐全后，将阶段标为 DONE，再推进依赖阶段。

独立审阅可由另一位工程师或单独的审阅会话承担；本规划编写不算独立审阅完成。

## 状态与问题等级

- 阶段状态：PLANNED、IN_PROGRESS、IN_REVIEW、CHANGES_REQUESTED、DONE、BLOCKED。
- 测试状态：PASS、FAIL、NOT_RUN、BLOCKED；确有负责人决定的豁免单列 WAIVED，并记录理由与范围。
- 审阅结论：APPROVE、REQUEST_CHANGES、BLOCKED。证据缺失不能给 APPROVE。
- P0：数据损坏、错误用药写入、敏感数据暴露等严重问题。
- P1：重复记录、确认假成功、关键入口不可用、升级破坏、明显错误或误导性状态。
- P2：不影响数据正确性的布局或次要体验问题；若违反本阶段明确验收项，仍阻塞阶段关闭。
- P3：建议项，不作为自动扩展范围的依据。

P0/P1 必须关闭。其余未完成必交付项只有经过负责人明确调整版本范围后才可延期；
验收表保留延期/豁免记录，不能转换成 PASS。

## 分阶段必查项

| 阶段 | 技术审阅重点 | 产品/宿主检查 | 关闭证据 |
|---|---|---|---|
| A | 基线、字段缺口、动作语义、预算方法 | 全样式状态稿和尺寸 | 规格无未定关键项，基线可复测 |
| B | 单一事实来源、配置隔离、旧值回退、协议新旧组合 | 原 Widget 配置升级后保留 | 契约/兼容测试、字段映射表 |
| C | 精确 occurrence、幂等、写入失败、批量刷新 | 四样式、双 launcher、多实例 | 自动化结果及真实宿主截图/操作 |
| D | PK 数值一致性、采样上限、计算共享、缓存失效 | 图表轴、单位、时间和空态 | 数值对照、截图、预算结果 |
| E | 回执、断连/重试、快照顺序、跨版本兼容 | 三 Tile、真表触控、旧 Tile | Phone/Watch 成对测试及真表证据 |
| F | provider 生命周期、有效期、更新合并 | 三数据源、不同槽位、环境模式 | 真实表盘证据和后台记录 |
| G | 升级、全入口一致性、相关核心回归、签名包 | 完整用户流程与最终视觉 | 完整验收表和最终独立结论 |

## 必测场景矩阵

| 组 | 场景 | 预期 |
|---|---|---|
| 数据 | 无计划、停用计划、无记录、今日无任务、部分/全部完成 | 空态明确，计数来源正确，无 NaN/伪零浓度 |
| 数据 | 同药多槽位、同一时刻多 occurrence、超出展示上限 | 不按药名/planId 合并任务，截断明确，统计不截断 |
| 动作 | 双击、多 Widget 同时点击、通知/Phone/Wear 同时确认 | 同一事项遵循现有并发与幂等语义，无重复记录 |
| 动作 | 旧按钮、方案修改/删除、写入异常、记录撤销 | 不写错对象，不假成功，已提交结果最终一致 |
| 时间 | 跨午夜、时区切换、DST 重复/缺失小时、12/24 小时制 | 复用领域时间规则，今日范围与显示一致 |
| 生命周期 | 进程被杀、重启、launcher 重建、添加/删除/恢复实例 | 配置隔离，旧实例可用，不泄漏无主后台工作 |
| Wear | 断连、重连、过期缓存、乱序/重复结果、Phone 恢复 | 不把旧数据当新数据，不把发送成功当持久化成功 |
| 兼容 | 旧 Phone+新 Watch、新 Phone+旧 Watch、两端新版 | 缺字段可解释，旧入口保持可用，无解码崩溃或误记 |
| 视觉 | 最小/中/大尺寸、长药名、大字体、深浅色、圆形屏 | 核心信息/按钮不裁切，对比与无障碍描述可用 |
| 性能 | EMPTY/STEADY/DENSE，1/3/5 Widget，多个 Tile/provider | 达到 A 冻结预算，不随展示面重复完整计算或轮询 |
| 升级 | v1.5.0 覆盖升级及备份恢复后的刷新 | 数据和配置兼容，派生展示与恢复后权威数据一致 |

设备至少覆盖：Phone 最低支持 API 与当前目标 API、真实 Phone、两个 launcher 宿主、
Wear 模拟器与真实圆形手表、兼容 Complication 表盘的两种槽位/布局。
设备缺失时记录 BLOCKED 和待补证据，不用模拟器替代真机结论。

## 自动化与测量方法

- 优先扩展现有 `WidgetPresentationTest`、`WidgetWorkTest`、`WidgetAppearanceTest`、
  `WidgetUiTest`、`WidgetRemoteViewsTest` 和 `ReceiverWidgetProductionCutoverTest`。
- Wear 复用 `WearAppSnapshotCodecTest`、confirmation/undo 协议测试、
  `WearAppSnapshotBuilderTest`、`WearAppStateTest` 等；新 provider 补行为测试，
  重点测试数据不可用、过期与点击目标，不写只重复字段赋值的测试。
- 固定 Clock、ZoneId、输入事件与设备条件；数值测试比较源引擎结果，UI 格式化容差单独定义。
- 每批运行受影响模块的 JVM 测试、编译和相关设备测试；涉及 manifest/资源时加对应 lint。
  G 阶段运行 `:experience-core:test`、`:app:testDebugUnitTest`、`:wear:testDebugUnitTest`、
  Phone/Wear 构建与 lint，并按设备分别执行相关 connected tests。
  正式命令及类名由实施者在当时 Gradle 配置上确认后记入证据。
- 性能先预热，再在同机同数据重复采样，报告样本数、中位数、尾部值、PK 调用次数、
  刷新请求及唤醒数量。实际刷新延迟另记，不以函数耗时代替系统宿主刷新时间。
- 沿用 `V15WidgetPerformanceDeviceTest` 和固定 PK 数据集作为起点；无有效采样不得宣称性能或耗电改善。
- 测试失败时记录具体用例；若怀疑环境/既有失败，在同环境重跑基线对照，不能仅凭失败数量相等排除回归。

## 实施时建立的验收记录

A 阶段建立 `V16_ACCEPTANCE.md`，后续逐批更新，至少使用以下字段：

| 阶段/用例 | 预期 | 起点/候选提交 | 设备与数据集 | 命令或操作 | 结果 | 证据路径 | 审阅者/日期 | 问题与复核 |
|---|---|---|---|---|---|---|---|---|
| A–G 待实施 | 对应计划和规格 | 待填 | 待填 | 待填 | NOT_RUN | 待填 | 待填 | 待填 |

每份阶段审阅报告应写明：范围、发现的问题（等级/文件位置/触发条件/实际与预期）、
独立验证、未测范围、最终结论。截图必须注明样式、设备/宿主、尺寸、状态与候选版本。
发布验收以最终候选提交为准；候选变更后，复核变更影响并更新证据，不能直接沿用旧结论。

## G 发布关闭条件

- A–F 全部必交付目标已验收或有明确的范围调整记录；无开放 P0/P1。
- 原 Widget/Tile 和新展示面均能在真实宿主工作，升级保留配置与数据。
- 动作一致性、时间边界、旧版本兼容与 PK 数值回归通过。
- 达到冻结的性能/后台预算；任何豁免明确记录，不作改善声明。
- 技术独立审阅和产品/视觉审阅通过，最终 Phone/Wear 发布包安装验证通过。
- 发布说明与功能矩阵准确反映交付内容和明确延期项，发布操作按项目现有流程执行。
