v1.7.4 settled navigation motion — corrected route-edge policy
==============================================================

Edge tracking (pure preview + commit):
  preview(route) only reads previousRoute and nextId and returns an edge.
  commit(edge) advances only when edge.id == nextId and the edge's from-route
  still matches the committed route. Therefore:
  - abandoned previews leave tracker state unchanged
  - repeated SideEffect calls for a cached edge are harmless
  - each successful route change gets exactly one fresh id
  - forward and Back both produce exactly one edge each
  - unrelated recomposition cannot fabricate a new edge
  - startup (previous = null -> start destination) does not cross the chrome
    boundary, so no fabricated motion event

Pure suite proof sequence:
  History -> Insights -> History -> Insights yields strictly increasing ids and
  true boundary classification for every edge. Home -> Records gets one fresh id
  after repeated same-edge commits.

Motion policy matrix remains unchanged:
  chrome-changing: History <-> Insights, History <-> Retrospective PK,
    History <-> Timeline, Settings <-> About, Settings <-> Google Drive backup/restore
  same-geometry: Home <-> Records <-> History <-> Medication Plans <-> Settings,
    Insights <-> Retrospective, Retrospective <-> Timeline, About <-> Disclosures
